title: Контекст и сессии
description: Что видит агент на шаге — объявленный контекст, выходы предыдущих работ, общая сессия.
---

Агент видит не «всё, что найдёт», а то, что ему объявили. Контекст собирается движком детерминированно: одинаковый вход даёт одинаковый промпт.

## Три уровня

```yaml
context:                         # пайплайн — видят все агентские шаги
  - AGENTS.md
  - text: Сгенерированные файлы в build/ не трогать.

jobs:
  implement:
    context:                     # работа
      - "openspec/changes/${inputs.change}/**/*.md"
    steps:
      - id: code
        agent: claude
        context:                 # шаг
          - path: reports/plan.json
            mode: inline
        context_exclude: ["build/**"]
```

Склейка сверху вниз: пайплайн → работа → шаг; перед ними — блок с выходами предыдущих работ. Записи идут в порядке объявления, глобы раскрываются сортированными. Мелкие файлы вставляются целиком, крупные передаются путём — агент прочитает их сам. `context_inherit: false` оставляет шагу только собственный контекст.

## Пределы и запреты

- `context.max_tokens` ограничивает собранный контекст шага и проверяется **до** запуска агента: один неудачный глоб не отправит репозиторий целиком. При превышении крупные вставки понижаются до ссылок, а если не помогло — шаг падает, не тратя токенов.
- Пути под `context.deny` из конфигурации не попадают в контекст никогда.
- `required: true` у глоба роняет шаг, если глоб ничего не нашёл, — вместо молча обеднённого контекста.

## Посмотреть до запуска

```bash
burnex context --job implement --step code
```

покажет записи, их источник, способ передачи и оценку размера. В прогоне то же лежит в `context.json` шага.

## Сессии

Агентские шаги одной работы по умолчанию идут в **общей сессии** (`session: shared`): второй шаг видит диалог первого, общий контекст отправляется один раз, и работает кеш промптов. `session: per_step` даёт каждому шагу свою сессию — и возможность переисполнить шаг в одиночку при `resume`. Работы общаются между собой не диалогом, а файлами — своими JSON-выходами.
