title: Решения человека
description: Шаг decision — объявленная точка, где прогон ждёт человека.
---

Человек в burnex — не «оператор, который следит за агентом», а исполнитель объявленного шага. Шаг `decision` останавливает прогон и ждёт, пока человек выберет один из названных исходов.

```yaml
- id: gate
  decision:
    prompt: Применить план к рабочему дереву?
    outcomes:
      approve: continue
      deny: { effect: reject, label: Отклонить }
      redo: { effect: restart, label: Проверить заново }
    deadline: 1h
    on_expire: deny
```

## Исходы

Эффектов ровно три, набор закрыт:

| Эффект | Что происходит |
|---|---|
| `continue` | шаг успешен, прогон идёт дальше |
| `reject` | прогон останавливается с причиной «отклонено — `<причина>`»; причина обязательна |
| `restart` | прогон останавливается и возобновляется с указанного шага |

`deadline` — срок от начала ожидания, `on_expire` — исход по его истечении (не `restart`: прогон, перезапускающий себя без человека, крутился бы по кругу). Выход шага — `outcome`, `effect`, `by`, `reason` — доступен работам ниже по графу.

## Как ответить

```bash
burnex decide <прогон> approve
burnex decide <прогон> deny --reason "рано"
burnex decide <прогон> redo --from check/inspect
```

или на экране «Решения» витрины (`burnex up`). Ожидание видно в `burnex status`, переживает перезапуск демона витрины, а статус прогона остаётся `running`.

## Где ставить

Перед необратимым: слиянием в main, публикацией, применением плана к живому окружению. Всё, что можно решить проверкой кодом, лучше решать проверкой — человек нужен там, где нужен выбор.
