Каждый запуск пайплайна — **прогон** со своим каталогом в `~/.burnex/runs/<проект>/<время>-<id>/`. Туда пишется всё: замок раскрытого пайплайна, состояние, события, а по каждой попытке каждого шага — промпт, собранный контекст, вывод, структурированный результат, вердикты проверок и расход.

## Команды

| Команда | Что показывает или делает |
|---|---|
| `burnex status [--run <id>]` | итог прогона по работам, причину отказа, ожидающие решения |
| `burnex logs <id> [<работа>/<шаг>] [--follow]` | вывод шага |
| `burnex usage <id>` | токены и деньги по работам, шагам и попыткам |
| `burnex diff <a> <b>` | чем различаются два прогона |
| `burnex resume <id> [--from <работа/шаг>]` | новый прогон, переиспользующий успешные шаги старого |
| `burnex apply <id>` | наложить результат прогона в отдельном дереве на текущее |
| `burnex gc [--older-than 30d]` | убрать старые прогоны |

## Возобновление

`burnex resume` создаёт новый прогон: шаги, чьи входы не изменились и которые прошли, берутся из старого, остальное исполняется заново. Входы шага — его ключ: промпт, контекст, модель, файлы, которые он читает. Поправили промпт третьей работы — первые две не перезапустятся. Шаги общей сессии возобновляются работой целиком.

## Витрина

```bash
burnex up      # поднять
burnex down    # остановить
```

Один локальный демон наблюдает за прогонами всех проектов и показывает их живьём: граф работ, вход и выход каждой работы, файлы журнала, разрез контекста агентских шагов, расход. Там же — экран «Решения» для шагов `decision`, запуск пайплайнов, настройка агентов и моделей, стратегии ревью и обсуждения.

## Объяснимость

- `burnex config` — итоговая конфигурация с источником каждого значения.
- `burnex config --pipeline <файл>` — кто исполнит каждый шаг: бэкенд, модель, effort и откуда они взялись.
- `burnex context` — что увидит шаг, до запуска.
- `burnex lint` — структура, ссылки, бюджеты, до первого токена.
