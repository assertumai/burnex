**Пайплайн** — YAML-документ (`burnex.yml` или `.burnex/pipelines/<имя>.yml`) с графом **работ**. **Работа** — последовательность шагов с собственным бюджетом, условием повтора и одним структурированным выходом.

```yaml
version: 1
kind: pipeline
name: implement

inputs:
  change: { type: string, required: true }

jobs:
  plan:
    steps: [...]
  implement:
    needs: [plan]             # после plan
    steps: [...]
  triage:
    needs: all
    on: failure               # только если что-то упало
    steps: [...]
```

## Граф, а не сценарий

- `needs` задаёт зависимости. Работы без взаимных зависимостей идут параллельно в пределах `concurrency` (по умолчанию 1).
- `on: success | failure | always` — условие по исходу зависимостей, `if:` — по данным: `if: "jobs.plan.output.risk == 'high'"`. Выражения видят входы, статусы и выходы работ.
- `fail_fast: true` (по умолчанию): первый отказ останавливает запуск новых работ, уже идущие доводятся до конца, затем исполняются работы с `on: failure`.
- Цикл без предела, недостижимая работа, ссылка на несуществующую — ошибки `burnex lint`, до запуска.

## Выход работы

Работа отдаёт один JSON: движок берёт его из шага `output.from` (по умолчанию — последний агентский) и проверяет схемой `output.schema`. Файл пишет движок, а не агент. Выходы предшественников **автоматически** попадают в контекст следующих агентских работ; управляет этим `context_upstream`.

```yaml
  plan:
    output: { from: draft, schema: ./schemas/plan.json }
```

## Работа в отдельном файле

Работа не знает о пайплайне: она описывает только что делает, свой бюджет и условие сходимости. Зависимости, условия и окружение задаются на месте подключения — поэтому одну работу можно переиспользовать в разных пайплайнах.

```yaml
jobs:
  review:
    uses: .burnex/jobs/review.yml
    needs: [implement]
```

## Рабочая директория

`workspace.mode`: `cwd` — работать прямо в каталоге проекта, `worktree` — в отдельном git worktree, `copy` — в копии. Результат прогона в отдельном дереве переносится на текущее командой `burnex apply`.
