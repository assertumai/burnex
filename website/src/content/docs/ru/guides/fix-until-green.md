---
title: Чинить до зелёных тестов
description: Агент чинит, код проверяет, цикл ограничен итерациями и бюджетом.
---

Задача: агент чинит падающие тесты, пока они не станут зелёными, — но не бесконечно, не дороже заданного и не трогая сами тесты.

```yaml
version: 1
kind: pipeline
name: fix-tests

budget: { tokens: 1M, cost: 5, wallclock: 30m }

jobs:
  fix:
    until:
      max_iterations: 3
      check: [{ cmd: npm test }]          # судит код, а не агент
    steps:
      - id: repair
        agent: claude
        prompt: |
          Почини падающие тесты. Сами тесты не меняй.
          Если причина в тесте, а не в коде — объясни и ничего не правь.
        permissions: { mode: acceptEdits }
        expect:
          - changed_only: ["src/**"]      # правки только в src/
        attempts: { max: 2 }

  verify:
    needs: [fix]
    steps:
      - id: lint
        run: [npm, run, lint]
        expect: [{ exit_code: 0 }]
```

## Что здесь происходит

1. Шаг `repair` правит код. Если он тронул что-то вне `src/`, проверка `changed_only` роняет попытку, и `attempts` даёт вторую.
2. После шагов работы движок запускает `npm test`. Красный — новая итерация, и вывод упавших тестов попадает агенту в контекст.
3. Три итерации без зелёного — работа падает с причиной `until_not_met`, `verify` не запускается.
4. Бюджет прогона обрывает всё, что упрётся в 1M токенов, $5 или 30 минут.

## Проверьте до запуска

```bash
burnex lint burnex.yml
```

`lint` предупредит, что у работы с циклом нет собственного бюджета, и напечатает худший случай — сколько исполнений шагов возможно.
