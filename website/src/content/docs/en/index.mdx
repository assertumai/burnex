	<Card title="Deterministic work is code" icon="setting">
		Job order, branching, retries and budgets are computed by the engine from the declared graph, not by a model on the fly. `burnex lint` catches cycles, broken references and unbounded loops before the first token is spent.
	</Card>
	<Card title="Any agent, any role" icon="puzzle">
		Claude, Codex and Cursor can work in one pipeline: one writes, another reviews, a third consolidates a discussion. An agent is a step type, not the orchestrator.
	</Card>
	<Card title="A contract on every step" icon="approve-check">
		Agent output goes through the checks you declared — schema, tests, edit boundaries; whatever fails does not move on. The agent's context is declared too: `burnex context` shows exactly what a step will see.
	</Card>
	<Card title="People where they matter, seeing everything" icon="comment-alt">
		A `decision` step pauses the run and waits for a call, with a deadline and a default outcome. `burnex up` shows runs live, and every step is written to the run log.
	</Card>
</CardGrid>

## What a pipeline looks like

Claude fixes the code until `npm test` passes, editing only `src/`. Codex reviews the diff and answers by schema. A person accepts or rejects.
