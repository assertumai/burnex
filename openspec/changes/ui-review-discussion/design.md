## Context

Детали прогона (`ui/src/pages/RunDetail.tsx`) показывают вывод агентского
шага разобранным ходом (`ui-dashboard`, «Вывод агентского шага
показывается разобранным ходом»). Живые обновления идут через
`ui/src/live.ts`. Шаг `review:` после этапов 2 и 3 пишет
`participants/<id>/`, `discussion.ndjson` (форма A2A `Message`) и события
`review.participant.*`, `review.message`, `review.consensus`,
`review.no_consensus`.

## Goals / Non-Goals

**Goals:**

- Ход ревью читается как переписка: кто, что, с чем согласен, чем кончилось.
- Видно, сколько реплик осталось и во что обошёлся каждый участник.
- Лента обновляется по ходу шага.

**Non-Goals:**

- Вмешательство человека в обсуждение (написать реплику, остановить
  раунд). Шаг для человека — `decision`.
- Отдельная страница обсуждения: лента живёт в деталях прогона на месте
  вывода шага.

## Decisions

### 1. Источник данных — журнал, а не поток бэкенда

Лента строится сервером из `discussion.ndjson` и `participants/*/step.json`
(для `independent` — только из `participants/*/output.json`) и отдаётся
одной моделью: участники (id, роль, агент, модель, цвет-индекс), записи
ленты (сообщение / предложение / системная строка / вердикт) и итог.
Живые события `review.*` несут `messageId`, и клиент дочитывает только
новые записи. Модель ленты не зависит от бэкенда участника.

### 2. Вид

- Сообщения ревьюеров — слева, вердикт агрегатора — справа, как
  собственные сообщения в мессенджере. Агрегатор — «наша сторона», он
  выносит итог.
- Цвет участника — по индексу в стратегии из палитры токенов витрины, а не
  по бэкенду: два ревьюера на одном бэкенде должны различаться.
- Метка позиции — бейдж: «предлагает» (нейтральный), «согласен» (успех),
  «против» (опасность). Ответ на предложение — цитата-полоса с его
  кратким содержанием и id.
- Счётчик `n/лимит` — в углу сообщения; сообщение невалидной реплики
  помечено «реплика не прошла схему».
- Системные строки — по центру, приглушённые: «Раунд 2», «Ревьюер tests
  не дал находок: таймаут», «Консенсус по предложению p2», «Без
  консенсуса: исчерпан лимит».
- Клик по аватару или сообщению открывает разобранный ход этого участника
  тем же компонентом, что у агентского шага.

### 3. Боковая панель

Три блока: «Лимит реплик» (по ревьюеру `n/лимит`, исчерпанные приглушены),
«Предложения» (id, автор, статус), «Расход» (по участникам и итог шага,
время). На узкой ширине панель уходит под ленту.

### 4. Доступность

Лента — список (`role="log"`, `aria-live="polite"` во время исполнения);
у каждого сообщения текстовая подпись роли и позиции, а не только цвет.

## Risks / Trade-offs

- [Длинное обсуждение] → лимит ограничивает объём сверху; раунды
  сворачиваются, кроме последнего, если реплик больше 30.
- [Журнал прогона прошлой версии без `discussion.ndjson`] → шаг без ленты
  показывается списком участников и выходом агрегатора.
