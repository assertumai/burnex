## ADDED Requirements

### Requirement: Шаг review показывается лентой обсуждения

Детали прогона SHALL показывать шаг вида `review` лентой в виде переписки, а не разобранным ходом одного агента. Каждый участник MUST иметь аватар с инициалами `id`, цвет по позиции в стратегии и подпись агента и модели. Первые сообщения ревьюеров MUST показывать их независимые находки. Реплика обсуждения MUST показываться сообщением с текстовой меткой позиции («предлагает», «согласен», «против»), цитатой предложения, на которое она отвечает, и счётчиком реплик ревьюера `n/лимит`; невалидная реплика MUST быть помечена. Начало раунда, ревьюер без находок и исход обсуждения MUST показываться системными строками. Вердикт агрегатора MUST быть последним сообщением, выровненным на противоположную ревьюерам сторону. В режиме `independent` лента MUST показывать находки и вердикт без раундов.

#### Scenario: Обсуждение с консенсусом

- **WHEN** пользователь открывает шаг `review`, чьё обсуждение прошло два раунда и закончилось консенсусом по `p2`
- **THEN** он видит находки трёх ревьюеров, реплики двух раундов с метками позиций и цитатами, строку «Консенсус по предложению p2» и вердикт агрегатора последним сообщением

#### Scenario: Ревьюер без находок

- **WHEN** ревьюер `tests` не дал находок по таймауту
- **THEN** лента содержит системную строку, называющую `tests` и причину

#### Scenario: Режим independent

- **WHEN** шаг исполнен в режиме `independent`
- **THEN** лента содержит находки каждого ревьюера и вердикт агрегатора без строк раундов

### Requirement: Боковая панель ленты показывает лимит, предложения и расход

Рядом с лентой SHALL показываться остаток лимита реплик по каждому ревьюеру, список предложений с автором и статусом (действующее, принято консенсусом, без поддержки) и расход и время по каждому участнику и по шагу. На узкой ширине панель MUST располагаться под лентой.

#### Scenario: Исчерпанный лимит

- **WHEN** ревьюер отправил все реплики лимита
- **THEN** его строка в блоке лимита показывает `лимит/лимит` и отмечена исчерпанной

### Requirement: Лента обновляется по ходу шага и ведёт к ходу участника

Пока шаг `review` исполняется, лента SHALL дополняться по событиям `review.participant.*`, `review.message`, `review.consensus` и `review.no_consensus` без перезагрузки страницы и объявляться вспомогательным технологиям как обновляемый журнал. Выбор сообщения или аватара участника MUST открывать разобранный ход этого участника тем же представлением, что у агентского шага, с доступом к его `stdout.log`. Шаг `review` из журнала без `discussion.ndjson` MUST показываться списком участников и выходом агрегатора.

#### Scenario: Новая реплика по ходу

- **WHEN** во время исполнения ревьюер отправил реплику
- **THEN** сообщение появляется в открытой ленте без перезагрузки

#### Scenario: Ход участника

- **WHEN** пользователь выбирает сообщение ревьюера `security`
- **THEN** открывается разобранный ход сессии `security` с вызовами инструментов и ссылкой на его `stdout.log`
