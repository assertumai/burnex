## ADDED Requirements

### Requirement: Сайт состоит из рукописного слоя и справочника

Сайт документации SHALL собираться пакетом `website/` из двух частей. Рукописный
слой — главная, «Начало», «Понятия», «Руководства» — MUST храниться в Git в
`website/src/content/docs/ru/`. Справочник SHALL собираться из страниц `docs/`,
перечисленных в манифесте `website/pages.mjs`: исходники MUST оставаться в
`docs/`, синхронизированные копии MUST лежать в исключённом из Git каталоге
`website/src/content/docs/ru/reference/`, и синхронизация MUST очищать только
его. Заголовок страницы справочника MUST браться из первого заголовка первого
уровня исходника, а сам этот заголовок из тела MUST убираться. Страница,
указанная в манифесте, но отсутствующая в `docs/`, MUST останавливать сборку.

#### Scenario: Страница справочника попадает на сайт

- **WHEN** манифест содержит `config`, а `docs/config.md` начинается с `# Конфигурация`
- **THEN** сайт отдаёт `/burnex/ru/reference/config/` с заголовком «Конфигурация» в разделе «Справочник» боковой навигации

#### Scenario: Синхронизация не трогает рукописные страницы

- **WHEN** выполняется `npm run sync`, а в `ru/start/first-run.mdx` есть рукописная страница
- **THEN** каталог `ru/reference/` пересоздаётся, а `ru/start/first-run.mdx` остаётся на месте

#### Scenario: Внутренний документ не публикуется

- **WHEN** `docs/proposals.md` не указан в манифесте
- **THEN** сайт не содержит его страницы и не находит его текст поиском

#### Scenario: Пропавший исходник

- **WHEN** манифест указывает страницу, файла которой нет в `docs/`
- **THEN** сборка завершается ошибкой с именем отсутствующего файла

### Requirement: Адреса с явной локалью и переадресация прежних

Страницы сайта SHALL иметь адреса с явной локалью `/burnex/ru/…`; корень
`/burnex/` MUST быть статической страницей-переадресацией на `/burnex/ru/` с
`rel=canonical` и видимой ссылкой на язык. Адрес страницы этапа 1
(`/burnex/<имя>/`) MUST вести на её место в справочнике, а адрес страницы,
снятой с сайта, — на её исходник в GitHub. Ссылка на собранном сайте от корня
домена мимо базы `/burnex/` MUST считаться битой проверкой ссылок.

#### Scenario: Прежний адрес справочника

- **WHEN** читатель открывает `/burnex/config/`
- **THEN** он попадает на `/burnex/ru/reference/config/`

#### Scenario: Снятая с сайта страница

- **WHEN** читатель открывает `/burnex/backlog/`
- **THEN** он попадает на `https://github.com/assertumai/burnex/blob/main/docs/backlog.md`

### Requirement: Ссылки внутри справочника ведут на сайт или в репозиторий

Ссылка в Markdown страницы справочника на страницу из манифеста SHALL
переписываться (`config.md`, `docs/config.md`, с якорем или без) в адрес этой
страницы на сайте с локалью и сохранением якоря. Относительная ссылка на любой
другой файл репозитория SHALL переписываться в адрес файла на GitHub в ветке
`main`. Абсолютные адреса, ссылки внутри блоков кода и ссылки рукописных
страниц MUST оставаться без изменений.

#### Scenario: Ссылка на соседнюю страницу с якорем

- **WHEN** `docs/plugins.md` ссылается на `config.md#слои`
- **THEN** на сайте ссылка ведёт на `/burnex/ru/reference/config/#слои`

#### Scenario: Ссылка на пример

- **WHEN** `docs/packages.md` ссылается на `../examples/packages/hello`
- **THEN** на сайте ссылка ведёт на `https://github.com/assertumai/burnex/blob/main/examples/packages/hello`

### Requirement: Тема сайта берётся из палитры приложения

Цвета сайта SHALL генерироваться при сборке из токенов веб-UI
`ui/src/styles.css`: блок `:root` — светлая тема, блок
`@media (prefers-color-scheme: dark)` — тёмная; тема сайта MUST переключаться
атрибутом `data-theme`, а не медиазапросом. Отсутствие ожидаемого токена MUST
останавливать сборку. Маскот и favicon MUST браться из `ui/src/assets/`.
Проверка сайта MUST проваливаться, если контраст ключевой пары (текст, ссылки,
текст кнопки, вторичный текст на фоне и в боковой колонке) в любой теме ниже
WCAG AA 4.5.

#### Scenario: Правка палитры ломает читаемость

- **WHEN** `--accent-foreground` светлой темы в `ui/src/styles.css` меняется на цвет с контрастом 4.1 к `--background`
- **THEN** `npm run check` в `website/` завершается ошибкой, называющей тему и пару

#### Scenario: Пропал токен

- **WHEN** из тёмного блока `ui/src/styles.css` удалён `--primary`
- **THEN** `npm run sync` завершается ошибкой «в теме dark нет токенов: --primary»

### Requirement: Пример главной проверяем и вставляется из файла

Пайплайн, показанный на главной, SHALL вставляться из `examples/home/burnex.yml`
при сборке, а не копией в тексте страницы, и MUST проходить `burnex lint` в
тестовом наборе движка при подключённом в глобальной конфигурации плагине Codex.

#### Scenario: Пример разошёлся с форматом

- **WHEN** формат пайплайна меняется так, что `examples/home/burnex.yml` перестаёт проходить lint
- **THEN** тест `examples/home` проваливается

### Requirement: Предварительная публикация помечена

Каждая страница сайта SHALL показывать баннер предварительной версии с коротким
SHA коммита сборки, пока линии версий не введены, — и рукописная, и справочника.
Страница справочника MUST ссылаться «редактировать» на исходник в `docs/`,
рукописная — на свой файл в `website/`.

#### Scenario: Баннер с SHA

- **WHEN** сайт собран из коммита `d23a5753`
- **THEN** каждая страница показывает баннер, содержащий `d23a575`

### Requirement: Публикация на GitHub Pages из main

Workflow `docs` SHALL собирать и проверять сайт в каждом PR, затрагивающем
`docs/`, `README.md`, `website/`, `examples/home/` или бренд-источники в `ui/src/`,
без публикации, и при push в `main` — собирать и публиковать один артефакт
через `actions/deploy-pages`. Права `pages: write` и `id-token: write` MUST
выдаваться только задаче публикации; публикации MUST не выполняться параллельно.

#### Scenario: PR не публикует

- **WHEN** PR меняет `docs/config.md`
- **THEN** workflow собирает сайт и не запускает задачу публикации
