## ADDED Requirements

### Requirement: Сайт собирается из docs/ без переноса исходников

Сайт документации SHALL собираться пакетом `website/` из страниц, перечисленных
в манифесте `website/pages.mjs`, и из `README.md` как главной. Исходники страниц
MUST оставаться в `docs/`; сгенерированный каталог контента MUST быть исключён
из Git. Заголовок страницы MUST браться из первого заголовка первого уровня
исходника, а сам этот заголовок из тела MUST убираться. Страница, указанная в
манифесте, но отсутствующая в `docs/`, MUST останавливать сборку.

#### Scenario: Публичная страница попадает на сайт

- **WHEN** манифест содержит `config` в разделе «Справочник», а `docs/config.md` начинается с `# Конфигурация`
- **THEN** сайт отдаёт `/burnex/config/` с заголовком «Конфигурация» и пунктом в разделе «Справочник» боковой навигации

#### Scenario: Внутренний документ не публикуется

- **WHEN** `docs/proposals.md` не указан в манифесте
- **THEN** сайт не содержит его страницы и не находит его текст поиском

#### Scenario: Пропавший исходник

- **WHEN** манифест указывает страницу, файла которой нет в `docs/`
- **THEN** сборка завершается ошибкой с именем отсутствующего файла

### Requirement: Ссылки внутри документации ведут на сайт или в репозиторий

Ссылка в Markdown на страницу из манифеста SHALL переписываться (`config.md`,
`docs/config.md`, с якорем или без) в адрес этой страницы на сайте с
сохранением якоря. Относительная ссылка на любой другой файл репозитория
SHALL переписываться в адрес файла на GitHub в ветке `main`. Абсолютные
адреса и ссылки внутри блоков кода MUST оставаться без изменений.

#### Scenario: Ссылка на соседнюю страницу с якорем

- **WHEN** `docs/plugins.md` ссылается на `config.md#слои`
- **THEN** на сайте ссылка ведёт на `/burnex/config/#слои`

#### Scenario: Ссылка на пример

- **WHEN** `docs/packages.md` ссылается на `../examples/packages/hello`
- **THEN** на сайте ссылка ведёт на `https://github.com/assertumai/burnex/blob/main/examples/packages/hello`

### Requirement: Предварительная публикация помечена

Пока линии версий не введены, каждая страница SHALL показывать баннер
предварительной версии с коротким SHA коммита сборки и ссылкой
«редактировать» на исходник в `docs/` (для главной — на `README.md`).

#### Scenario: Баннер с SHA

- **WHEN** сайт собран из коммита `d23a5753`
- **THEN** каждая страница показывает баннер, содержащий `d23a575`

### Requirement: Публикация на GitHub Pages из main

Workflow `docs` SHALL собирать сайт в каждом PR, затрагивающем `docs/`,
`README.md` или `website/`, без публикации, и при push в `main` — собирать и
публиковать один артефакт через `actions/deploy-pages`. Права `pages: write` и
`id-token: write` MUST выдаваться только задаче публикации; публикации MUST
не выполняться параллельно.

#### Scenario: PR не публикует

- **WHEN** PR меняет `docs/config.md`
- **THEN** workflow собирает сайт и не запускает задачу публикации
