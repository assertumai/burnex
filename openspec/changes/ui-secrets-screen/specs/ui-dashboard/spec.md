## ADDED Requirements

### Requirement: Экран «Secrets» показывает имена, провайдеры и статус секретов
Витрина SHALL отдавать `GET /api/secrets` и экран «Secrets» по маршруту `/secrets` в группе меню `system`: по каждому проекту корня прогонов — провайдеры секретов, зарегистрированные в реестре проекта, объявления `secrets:` известных пайплайнов (имя, переменная `env`, провайдер, параметры, пайплайны и шаги, которые его называют) и учётные данные `backends.<id>.credentials` конфигурации проекта. Каждая запись MUST нести статус `resolved`, `not-found` или `provider-unavailable` и, кроме `resolved`, причину теми же словами, какими отказал бы запуск.

#### Scenario: Секрет разрешается
- **WHEN** пайплайн проекта объявляет `gh-token` провайдером `env-file`, а файл и ключ на месте со значением не короче 8 символов
- **THEN** запись `gh-token` в ответе `GET /api/secrets` имеет статус `resolved`, провайдер `env-file` и пайплайн с шагом, который её называет

#### Scenario: Ключа нет в файле
- **WHEN** файл `env-file` есть, а ключа в нём нет
- **THEN** запись имеет статус `not-found` и причину, называющую файл и ключ

#### Scenario: Провайдер не зарегистрирован
- **WHEN** объявление называет провайдер, которого нет в реестре проекта
- **THEN** запись имеет статус `provider-unavailable` и причину со списком доступных провайдеров

#### Scenario: Связка ключей недоступна
- **WHEN** провайдер `keychain` вызван не на macOS, не ответил за таймаут или команда `security` не найдена
- **THEN** запись имеет статус `provider-unavailable`, а при отсутствии записи в связке ключей — `not-found`

#### Scenario: Провайдер не ответил за срок пробы
- **WHEN** провайдер не отвечает за срок проб проекта, в том числе не слушая сигнал отмены
- **THEN** ответ `GET /api/secrets` приходит не позже срока, запись имеет статус `provider-unavailable` с причиной об истёкшем сроке, остальные записи — свои статусы

#### Scenario: Объявленный, но не названный секрет
- **WHEN** секрет объявлен в `secrets:`, но ни один шаг его не называет
- **THEN** запись присутствует с признаком «не используется» и со своим статусом

#### Scenario: Пункт меню
- **WHEN** пользователь открывает витрину со встроенной таблицей маршрутов
- **THEN** в группе `system` есть пункт «Secrets», ведущий на `/secrets`

### Requirement: Значения секретов не покидают пробу
Ни ответ `GET /api/secrets`, ни экран «Secrets», ни журнал демона SHALL NOT содержать значение секрета или учётных данных: статус вычисляется тем же путём проверок, что и запуск, а полученное значение отбрасывается сразу после проверок и не кешируется.

#### Scenario: Значение-маркер не попадает в ответ
- **WHEN** `.env` проекта содержит для объявленного секрета значение-маркер и экран запрошен
- **THEN** тело ответа `GET /api/secrets` не содержит маркера ни в одном поле, а запись имеет статус `resolved`

#### Scenario: Значение-маркер не попадает на экран
- **WHEN** экран «Secrets» отрисован по ответу API
- **THEN** разметка экрана не содержит значения ни одного секрета

#### Scenario: Статус экрана совпадает с отказом запуска
- **WHEN** запуск пайплайна отказал бы с «Секрет X не разрешён: причина»
- **THEN** запись X на экране имеет статус, отличный от `resolved`, и ту же причину
