## Why

Секреты по имени (`secrets-named-providers`, `secrets-keychain-provider`)
объявляются верхним ключом `secrets:` пайплайна и записями
`backends.<id>.credentials` конфигурации, но витрина о них не знает ничего:
ни какие имена ждут пайплайны, ни каким провайдером они берутся, ни
разрешаются ли они на этой машине. Сейчас об этом узнают только по отказу
запуска — `Секрет gh-token не разрешён: …` — уже после нажатия Run
(`docs/ui-proposals.md`, п. 2: «провайдеры, имена секретов, статус; значения не
показывать»).

## What Changes

- **API `GET /api/secrets`** — строка поставки `screen-secrets`. По каждому
  проекту корня прогонов (тот же обход и та же проектная конфигурация, что у
  `GET /api/pipelines`):
  - провайдеры секретов, зарегистрированные в реестре проекта, с владельцем
    вклада (встроенный или плагин);
  - объявления `secrets:` известных пайплайнов: имя, переменная `env`,
    провайдер, параметры провайдера, пайплайны и шаги, которые секрет
    называют (объявленный, но никем не названный — помечен);
  - учётные данные бэкендов `backends.<id>.credentials` из конфигурации;
  - у каждой записи — статус `resolved` / `not-found` /
    `provider-unavailable` и причина отказа словами движка.
- **Значения не покидают разрешения.** Статус получается тем же путём
  проверок, что и запуск (`resolveTarget` в `src/parts/pipeline/run/secrets.ts`
  становится общей пробой); полученное значение отбрасывается сразу после
  проверок длины и перевода строки и не попадает ни в ответ, ни в кеш, ни в
  журнал демона.
- **Различимое «провайдер недоступен».** Аддитивно к поверхности
  `stepcast/pipeline`: класс ошибки `SecretProviderUnavailableError`, которым
  провайдер сообщает «я не могу работать здесь» (не macOS, таймаут связки
  ключей, нет команды). Встроенный `keychain` переходит на него; прочий отказ
  провайдера — `not-found`. Тексты отказов запуска не меняются.
- **Экран «Secrets»** — `ui/src/pages/Secrets.tsx` и `ui/src/screens/secrets.tsx`:
  проекты, провайдеры, таблица секретов и учётных данных с бейджем статуса и
  причиной; кнопка «Проверить снова».
- **Маршрут** `screen-secrets` на `/secrets`, `nav: { group: system, order: 8 }`.
- **Тесты**: ответ API на временном проекте с `env-file` (найден, нет ключа,
  нет файла), с незарегистрированным провайдером и с фальшивым `keychain`; в
  каждом — значение секрета не встречается в теле ответа; разметка экрана без
  значений; ожидания таблицы маршрутов.
- **Документация**: раздел «Секреты на витрине» в `docs/config.md`, ссылка из
  «Секреты» `docs/pipeline-format.md`.

## Impact

- Код: `src/parts/pipeline/run/secrets.ts` (общая проба),
  `src/parts/pipeline/secrets/keychain.ts`, `src/parts/pipeline/contract.ts`
  и поверхность `stepcast/pipeline` (новый класс ошибки),
  `src/parts/ui/screens/secrets/{declaration,server}.ts`, `src/parts/ui/secrets.ts`
  (свёртка ответа), `src/parts/ui/rows.ts`, `src/builtin/routes.yml`,
  `ui/src/pages/Secrets.tsx`, `ui/src/screens/secrets.tsx`, `ui/src/screens/index.ts`.
- API: новый `GET /api/secrets` (только чтение). Существующие маршруты не
  меняются.
- Побочный эффект: открытие экрана вызывает провайдеры — для `keychain` это
  `security find-generic-password` с прежним пятисекундным таймаутом.
- Зависимостей не добавляется.
