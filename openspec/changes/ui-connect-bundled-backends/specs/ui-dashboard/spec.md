## ADDED Requirements

### Requirement: Экран «Agents» перечисляет все поставляемые плагины бэкендов
Чтение настроек витрины (`GET /api/settings`) SHALL включать в перечень бэкендов каждый бэкенд каждого плагина, поставляемого пакетом подпутём `stepcast/backends/<имя>`, в том числе не объявленного в `plugins:`. Бэкенд без адаптера в реестре MUST иметь `available: false`, а если его плагин поставляется пакетом — поле `plugin` со спецификатором этого плагина; у подключённого бэкенда и у бэкенда, подключить который из витрины нечем, `plugin` MUST отсутствовать. Неподключённый бэкенд MUST NOT дублировать бэкенд того же имени, уже объявленный в конфигурации. Перечень поставляемых плагинов MUST совпадать с подпутями `./backends/*` поля `exports` в `package.json`; встроенный бэкенд `claude` в него MUST NOT входить.

#### Scenario: Чистая установка видит все три адаптера
- **WHEN** глобальный файл не объявляет `plugins:`, и витрина читает настройки
- **THEN** перечень содержит `claude` с `available: true` без `plugin`, а также `codex`, `cursor-agent` и `copilot` с `available: false` и `plugin`, равным `stepcast/backends/codex`, `stepcast/backends/cursor` и `stepcast/backends/copilot` соответственно
- **AND** у `codex` модель бэкенда — умолчание плагина с источником `plugin:codex`, у `cursor-agent` и `copilot` модель бэкенда не задана

#### Scenario: Подключённый бэкенд не дублируется заглушкой
- **WHEN** глобальный файл объявляет `plugins: [stepcast/backends/cursor]`
- **THEN** перечень содержит ровно одну запись `cursor-agent`, с `available: true` и без `plugin`
- **AND** `codex` и `copilot` по-прежнему перечислены с `available: false`

#### Scenario: Объявленный, но не поднявшийся адаптер подключать нечем
- **WHEN** глобальный файл уже объявляет `stepcast/backends/copilot`, но сборка состава отказала и адаптера в реестре нет
- **THEN** `copilot` перечислен с `available: false` и без `plugin`

#### Scenario: Каталог не отстаёт от пакета
- **WHEN** в `exports` пакета есть подпуть `./backends/<x>`, которого нет в перечне поставляемых плагинов, или наоборот
- **THEN** проверка репозитория падает

### Requirement: Правка настроек подключает поставляемый бэкенд по имени
Правка настроек витрины (`PUT /api/settings`) SHALL принимать поле `connect` — перечень имён бэкендов поставляемых плагинов — и дописывать в `plugins:` глобального файла спецификатор плагина каждого из них, если такой строки там ещё нет, сохраняя комментарии файла. Имя вне перечня поставляемых плагинов MUST отклонять всю правку до записи файла; так же MUST отклоняться имя, спецификатор которого уже объявлен в `plugins:`, а бэкенд не подключён. Поле `connectCodex: true` MUST действовать так же, как `connect: ["codex"]`. Агентом по умолчанию MUST разрешаться неподключённый бэкенд, только если та же правка его подключает; иначе правка MUST отклоняться отказом «not connected». Ответ правки MUST показывать подключённый бэкенд с `available: true` без перезапуска демона.

#### Scenario: Подключение Cursor из витрины
- **WHEN** витрина шлёт `PUT /api/settings` с `connect: ["cursor-agent"]` и `agent: "cursor-agent"`, а глобальный файл содержит комментарий и не объявляет `plugins:`
- **THEN** файл содержит `plugins:` со строкой `stepcast/backends/cursor` и `defaults.agent: cursor-agent`, комментарий сохранён
- **AND** в ответе `cursor-agent` имеет `available: true`, а `agent.value` равен `cursor-agent`

#### Scenario: Повторное подключение не дублирует строку
- **WHEN** глобальный файл уже объявляет `stepcast/backends/copilot`, и правка присылает `connect: ["copilot"]`
- **THEN** строка `stepcast/backends/copilot` встречается в `plugins:` ровно один раз

#### Scenario: Неизвестное имя отклоняет правку целиком
- **WHEN** правка присылает `connect: ["claude"]` или `connect: ["gemini"]` вместе с `effort: "high"`
- **THEN** ответ — отказ с именем бэкенда, а глобальный файл не изменён

#### Scenario: Прежний флаг Codex работает как раньше
- **WHEN** правка присылает `connectCodex: true` и `agent: "codex"`
- **THEN** результат тот же, что у `connect: ["codex"]` с `agent: "codex"`: в `plugins:` дописан `stepcast/backends/codex`, и `codex` в ответе доступен

#### Scenario: Неподключённый агент без подключения отклоняется
- **WHEN** правка присылает `agent: "copilot"` без `connect`, а `copilot` не подключён
- **THEN** ответ — отказ «Agent copilot is not connected», файл не изменён

#### Scenario: Подключение уже объявленного, но не поднявшегося адаптера отклоняется
- **WHEN** глобальный файл объявляет `stepcast/backends/copilot`, `copilot` не подключён, и правка присылает `connect: ["copilot"]`
- **THEN** ответ — отказ, называющий объявленный спецификатор, а глобальный файл не изменён

### Requirement: Вкладка Backends предлагает подключение каждого неподключённого поставляемого бэкенда
Карточка бэкенда на вкладке Backends экрана «Agents» SHALL нести одно действие подключения ровно тогда, когда бэкенд неподключён и поставляется пакетом (`available: false` и задан `plugin`). Отмеченное подключение MUST разрешать этот бэкенд в выборе агента по умолчанию до сохранения и MUST уходить в правку настроек полем `connect` с именем бэкенда.

#### Scenario: Отметка подключения Copilot
- **WHEN** на вкладке Backends у карточки `copilot` с пометкой «plugin not connected» отмечено «Connect copilot», и пользователь сохраняет
- **THEN** витрина шлёт `PUT /api/settings` с `connect: ["copilot"]`

#### Scenario: У подключённого бэкенда действия нет
- **WHEN** бэкенд `claude` или подключённый `codex` показан на вкладке Backends
- **THEN** действия подключения на его карточке нет
