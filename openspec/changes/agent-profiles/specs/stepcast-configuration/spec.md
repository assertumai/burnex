## ADDED Requirements

### Requirement: Профили агентов объявляются ключом agents

Конфигурация SHALL принимать ключ верхнего уровня `agents`, где ключ — имя профиля, а значение — запись с обязательным `backend` и необязательными `model`, `model_tier`, `effort` и `context`. Запись, объявившая одновременно `model` и `model_tier`, и запись с неизвестным полем MUST отклоняться разбором с указанием файла и пути ключа. `context` MUST приниматься той же схемой записей, что `context` шага. Ключ допустим в глобальном и в проектном файле; проектный профиль MUST заменять одноимённый глобальный целиком, а не по листьям. Профиль, чей `backend` не назван среди бэкендов, MUST отклонять раскрытие только тех пайплайнов, которые этим профилем исполняются, с указанием файла и пути `agents.<имя>.backend`.

#### Scenario: Профиль принимается

- **WHEN** `~/.burnex/config.yml` содержит `agents: { reviewer-strict: { backend: codex, model_tier: max, effort: high } }`
- **THEN** конфигурация разрешается без ошибки, и отчёт `burnex config` называет этот файл источником `agents.reviewer-strict`

#### Scenario: Проектный профиль заменяет глобальный целиком

- **WHEN** глобальный файл объявляет `agents.arch: { backend: claude, model_tier: deep, context: [{ text: "правила" }] }`, а проектный — `agents.arch: { backend: codex }`
- **THEN** действующий профиль `arch` — `{ backend: codex }` без контекста и уровня, его источник — проектный файл

#### Scenario: Модель и уровень в одном профиле

- **WHEN** профиль объявляет и `model: sonnet`, и `model_tier: fast`
- **THEN** разбор конфигурации отклоняется с указанием файла и пути `agents.<имя>`

### Requirement: Имя профиля не совпадает с default и с именем бэкенда

Имя профиля SHALL соответствовать `^[a-z][a-z0-9_-]*$`. Профиль `default` MUST отклоняться разбором: профиль `default` встроен и представляет `defaults.agent`, `defaults.model` и `defaults.effort`. Профиль, чьё имя совпадает с именем подключённого или поставляемого бэкенда, MUST отклоняться разбором с указанием файла, пути ключа и того, что имя бэкенда уже является неявным профилем.

#### Scenario: Объявлен default

- **WHEN** файл объявляет `agents: { default: { backend: claude } }`
- **THEN** разбор отклоняется, а подсказка называет ключи `defaults.agent`, `defaults.model` и `defaults.effort`

#### Scenario: Имя бэкенда

- **WHEN** файл объявляет `agents: { claude: { backend: claude, model_tier: deep } }`
- **THEN** разбор отклоняется с указанием файла и пути `agents.claude`

### Requirement: Пути контекста профиля разрешаются от слоя объявления

Относительный путь записи контекста профиля SHALL разрешаться от корня репозитория, если профиль объявлен проектным файлом, и от каталога `~/.burnex/`, если глобальным. Абсолютный путь и путь с `~/` MUST приниматься в обоих слоях как есть. Путь, разрешённый вне рабочего дерева, MUST допускаться для записи контекста профиля.

#### Scenario: Глобальный профиль

- **WHEN** глобальный профиль объявляет `context: [{ path: guides/security.md }]`
- **THEN** запись читает `~/.burnex/guides/security.md`

#### Scenario: Проектный профиль

- **WHEN** проектный профиль объявляет `context: [{ path: docs/review-rules.md }]`
- **THEN** запись читает `docs/review-rules.md` от корня репозитория

## MODIFIED Requirements

### Requirement: Запись выбора пользователя не роняет чужие пайплайны
Движок SHALL считать предупреждением, а не ошибкой, запись `step_agents`, которая называет работу или шаг, отсутствующие в пайплайне, или шаг не агентского вида. Запись `pipeline_agents` или `step_agents`, чей `agent` не назван ни среди профилей, ни среди бэкендов, SHALL отклонять раскрытие только того пайплайна, к которому запись относится, с указанием файла и пути ключа; подсказка MUST перечислять профили и бэкенды раздельно.

#### Scenario: Запись исчезнувшего шага
- **WHEN** `step_agents.p.old.gone` объявлена, а в пайплайне `p` нет работы `old`
- **THEN** `stepcast run` пайплайна `p` исполняется, а `stepcast config --pipeline` называет запись в списке записей без действия с причиной «шага нет в пайплайне»

#### Scenario: Неизвестный агент в записи другого пайплайна
- **WHEN** `pipeline_agents.other` объявляет `agent: nosuch`, а запускается пайплайн `p`
- **THEN** раскрытие пайплайна `p` проходит без ошибки

#### Scenario: Неизвестный агент в записи своего пайплайна
- **WHEN** `pipeline_agents.p` объявляет `agent: nosuch`, а запускается пайплайн `p`
- **THEN** раскрытие отклоняется с указанием файла конфигурации и пути `pipeline_agents.p.agent`, а подсказка перечисляет известные профили и бэкенды

#### Scenario: Запись называет профиль
- **WHEN** `pipeline_agents.p` объявляет `agent: reviewer-strict`, и такой профиль объявлен
- **THEN** раскрытие пайплайна `p` проходит без ошибки
