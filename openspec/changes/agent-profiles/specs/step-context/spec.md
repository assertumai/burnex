## ADDED Requirements

### Requirement: Контекст профиля агента — отдельный уровень перед пайплайном

Записи `context` профиля, которым исполняется агентский шаг, SHALL включаться в контекст шага отдельным уровнем «профиль», стоящим перед уровнем пайплайна. Уровень профиля MUST NOT сниматься ключом `context_inherit: false` и MUST NOT фильтроваться `context_exclude`. Он MUST подчиняться `context.deny` и `context.max_tokens` наравне с остальными уровнями. В зафиксированном составе контекста записи уровня MUST иметь источник `profile:<имя>`. В сессии, продолжающей диалог, контекст профиля MUST отправляться по правилам общего контекста сессии. Шаг, исполняемый неявным профилем бэкенда, уровня профиля не получает.

#### Scenario: Порядок уровней

- **WHEN** профиль, пайплайн, работа и шаг объявляют по одной записи `context`
- **THEN** собранный контекст содержит все четыре в порядке «профиль, пайплайн, работа, шаг»

#### Scenario: Отказ от наследования не снимает профиль

- **WHEN** шаг, исполняемый профилем с записью `text`, объявляет `context_inherit: false`
- **THEN** в контексте шага есть запись профиля и нет записей пайплайна и работы

#### Scenario: Запрет по пути действует

- **WHEN** запись контекста профиля указывает на файл под шаблоном `context.deny`
- **THEN** файл в контекст не попадает, а в `events.ndjson` появляется запись с путём и сработавшим шаблоном

#### Scenario: Источник в составе

- **WHEN** шаг исполняется профилем `reviewer-strict` с одной записью `path`
- **THEN** `context.json` содержит эту запись с источником `profile:reviewer-strict`
