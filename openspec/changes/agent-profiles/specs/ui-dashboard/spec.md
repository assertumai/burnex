## ADDED Requirements

### Requirement: Вкладка Profiles показывает и правит профили агентов

Вкладка **Profiles** экрана «Agents» SHALL перечислять встроенный профиль `default` первым, ссылкой на вкладку Default, а затем профили ключа `agents` по имени, с пометкой файла-источника и списком пайплайнов и шагов, исполняемых профилем. Витрина SHALL давать создавать, править и удалять профили глобального файла формой с полями имени, бэкенда, модели или уровня, effort и записей контекста вида `text` и `path`. Профили проектного файла MUST показываться только для чтения с указанием файла. Удаление профиля, который исполняет хотя бы один шаг, MUST требовать подтверждения, называющего эти шаги. Правка, которую разбор конфигурации отклонил бы, MUST отклоняться формой с тем же текстом до записи в файл. Выбор агента на вкладке Policy и в диалоге ручного запуска SHALL предлагать профили отдельной группой перед бэкендами.

#### Scenario: Создание профиля

- **WHEN** пользователь создаёт профиль `reviewer-strict` с бэкендом `codex`, уровнем `max` и текстовой записью контекста и сохраняет
- **THEN** глобальный файл конфигурации содержит `agents.reviewer-strict` с этими полями, и профиль появляется в выборе агента на вкладке Policy

#### Scenario: Проектный профиль

- **WHEN** проектный файл объявляет профиль `arch`
- **THEN** вкладка показывает `arch` с проектным файлом-источником и без органов правки

#### Scenario: Удаление используемого профиля

- **WHEN** пользователь удаляет профиль, которым исполняется шаг `self-improve/review/review-diff`
- **THEN** витрина просит подтверждения и называет этот шаг

#### Scenario: Имя бэкенда

- **WHEN** пользователь вводит имя профиля `claude`
- **THEN** форма отклоняет сохранение тем же текстом, что разбор конфигурации

## MODIFIED Requirements

### Requirement: Настройки агентов собраны одним экраном

Витрина SHALL показывать все настройки агентов одним экраном «Agents» с
пятью вкладками: **Default** — агент, модель и effort по умолчанию вместе с
областью действия модели по умолчанию и её размером; **Profiles** — профили
агентов; **Backends** — перечень
бэкендов с командой, доступностью плагина, включённостью, пометкой умолчания,
моделью бэкенда и исходом перечисления моделей; **Tiers** — общие уровни и
модели с effort по каждому агенту; **Policy** — по каждому пайплайну с именем
его `agent_policy` с файлом-источником, запись выбора агента на пайплайн и на
каждый агентский шаг. Отдельного экрана настроек в составе витрины MUST NOT
быть, а в меню SHALL быть один пункт для этих настроек. Правки вкладок
Default, Profiles, Backends и Tiers SHALL уходить одной записью в глобальный файл
конфигурации, и переключение вкладки MUST NOT сбрасывать несохранённый
черновик.

#### Scenario: Один пункт меню

- **WHEN** пользователь открывает витрину со встроенной таблицей маршрутов
- **THEN** в группе `system` меню есть пункт «Agents» и нет пункта «Settings»

#### Scenario: Модель по умолчанию рядом с уровнями

- **WHEN** глобальный `model` задан и перекрывает уровни
- **THEN** предупреждение об этом показано на том же экране, и поле, которое снимает значение, доступно на вкладке Default без перехода на другой экран

#### Scenario: Черновик переживает смену вкладки

- **WHEN** пользователь изменил модель бэкенда на вкладке Tiers и перешёл на вкладку Backends
- **THEN** изменение остаётся несохранённым черновиком, и кнопка сохранения по-прежнему активна

#### Scenario: Политика и выбор агента по пайплайнам

- **WHEN** пользователь открывает вкладку Policy
- **THEN** для каждого пайплайна с именем показаны `agent_policy` с файлом-источником и записи выбора агента на пайплайн и на каждый агентский шаг с подписями слоёв, а пайплайн без имени назван с причиной, по которой выбрать для него агента нельзя

#### Scenario: Черновик профиля переживает смену вкладки

- **WHEN** пользователь изменил уровень профиля на вкладке Profiles и перешёл на вкладку Tiers
- **THEN** изменение остаётся несохранённым черновиком, и кнопка сохранения по-прежнему активна

### Requirement: Вкладка экрана агентов — часть адреса

Вкладка экрана «Agents» SHALL выбираться необязательным параметром пути с
закрытым перечнем значений `default`, `profiles`, `backends`, `tiers`, `policy`; адрес без
параметра SHALL открывать вкладку Default. Переключение вкладки на экране SHALL
менять адрес, а не только состояние страницы. Значение вне перечня SHALL
оставаться неразобранным адресом, как любой неизвестный адрес витрины.

#### Scenario: Вкладка открывается по ссылке

- **WHEN** пользователь открывает `/agents/policy`
- **THEN** экран «Agents» показан с активной вкладкой Policy

#### Scenario: Вкладка профилей открывается по ссылке

- **WHEN** пользователь открывает `/agents/profiles`
- **THEN** экран «Agents» показан с активной вкладкой Profiles

#### Scenario: Переключение вкладки меняет адрес

- **WHEN** пользователь на `/agents` переключается на вкладку Tiers
- **THEN** адрес в строке браузера становится `/agents/tiers`

#### Scenario: Неизвестная вкладка

- **WHEN** пользователь открывает `/agents/other`
- **THEN** витрина показывает перечень маршрутов для неразобранного адреса, а не экран «Agents»
