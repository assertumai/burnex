## ADDED Requirements

### Requirement: Агент шага может быть назван профилем

Поле `agent` любого слоя выбора — шага, работы, корня документа, `defaults.agent`, `pipeline_agents`, `step_agents` и флага `--agent` — SHALL принимать имя профиля. Встроенный профиль `default` SHALL означать `defaults.agent`, `defaults.model` и `defaults.effort`, а имя каждого бэкенда — неявный профиль `{ backend: <имя> }` без модели, effort и контекста. Слой, чьё `agent` назвало профиль, SHALL считаться объявившим также `model`, `model_tier` и `effort` профиля в тех полях, которые он не объявил сам; агентом шага SHALL становиться `backend` профиля. Ранги слоёв, политика `agent_policy`, правило замены выбора модели и отбрасывание чужой модели MUST применяться к дописанному слою без изменений. Документ и конфигурация без ключа `agents` MUST раскрываться в те же шаги с теми же ключами шага, что до введения профилей.

#### Scenario: Профиль в шаге

- **WHEN** шаг объявляет `agent: reviewer-strict`, а профиль — `{ backend: codex, model_tier: max, effort: high }`
- **THEN** шаг исполняется агентом `codex` с моделью уровня `max` бэкенда `codex` и effort `high`

#### Scenario: Собственное поле слоя сильнее профиля

- **WHEN** шаг объявляет `agent: reviewer-strict` и `effort: low`
- **THEN** effort шага — `low`, а модель — из уровня `max` профиля

#### Scenario: Профиль из записи пользователя при force

- **WHEN** `agent_policy: force`, шаг объявляет `model: opus` и не объявляет `agent`, а `step_agents.p.review.check` объявляет `agent: reviewer-strict` с бэкендом `codex` и `model_tier: max`
- **THEN** агент шага — `codex`, модель `opus` шага отбрасывается как чужая `codex`, и шаг получает модель уровня `max` профиля

#### Scenario: Имя бэкенда сохраняет смысл

- **WHEN** шаг объявляет `agent: claude`, и ключ `agents` не объявлен ни одним слоем
- **THEN** раскрытие даёт тот же шаг и тот же ключ шага, что до введения профилей

#### Scenario: Неизвестное имя

- **WHEN** шаг объявляет `agent: nosuch`, и нет ни профиля, ни бэкенда с этим именем
- **THEN** раскрытие отклоняется с указанием файла и пути `agent`, а подсказка перечисляет профили и бэкенды раздельно

### Requirement: Файлы контекста профиля вне дерева входят в ключ шага

Ключ агентского шага SHALL включать отпечаток содержимого каждого файла контекста его профиля, лежащего вне рабочего дерева. Имя профиля MUST NOT входить в ключ шага.

#### Scenario: Правка файла вне дерева

- **WHEN** шаг исполняется профилем с записью контекста `~/.burnex/guides/security.md`, и между двумя прогонами меняется только этот файл
- **THEN** ключи шага в двух прогонах различаются, и шаг второго прогона не переиспользуется

#### Scenario: Переименование профиля

- **WHEN** профиль переименован без изменения содержимого, и шаг ссылается на новое имя
- **THEN** ключ шага совпадает с прежним

## MODIFIED Requirements

### Requirement: Происхождение агента, модели и effort записывается
Раскрытие SHALL записывать для каждого агентского шага слой, давший агента, слой, давший модель, и слой, давший effort. Слои — `step`, `job`, `pipeline`, `config`, `pipeline_agents`, `step_agents`, а для модели также `tier` и `backend`. Для слоёв конфигурации записывается файл, давший значение. Значение, пришедшее из профиля, записывается со слоем, назвавшим профиль, и с именем профиля; `pipeline.lock` печатает имя профиля шага. Отброшенная чужая модель записывается вместе со слоем, из которого пришла. Происхождение не входит в шаг, по которому считается ключ шага.

#### Scenario: Агент из записи пайплайна
- **WHEN** агента шага дал `pipeline_agents.p` из `~/.stepcast/config.yml`
- **THEN** происхождение агента шага — слой `pipeline_agents` с этим файлом

#### Scenario: Справочное поле не меняет ключ шага
- **WHEN** два раскрытия дают шагу одного агента и одну модель из разных слоёв
- **THEN** ключ шага у них совпадает

#### Scenario: Значение из профиля
- **WHEN** шаг объявляет `agent: reviewer-strict`, а профиль объявляет `model_tier: max`
- **THEN** происхождение агента — слой `step` с профилем `reviewer-strict`, происхождение модели — `tier` с профилем `reviewer-strict`, и `burnex config --pipeline` печатает имя профиля в строке шага
