## ADDED Requirements

### Requirement: Схема по итоговому тексту держится движком

Адаптер MAY объявлять возможность `schemaFromText` — бэкенд надёжно отдаёт итоговый текст ответа. Если вызов агента несёт схему (`output_schema` шага, схему участника шага `review`, схему хода защиты либо схему вердикта судьи), а адаптер не объявляет нативный структурированный вывод, но объявляет `schemaFromText`, движок SHALL:

- дописать схему в промпт вызова (и в сохраняемый `prompt.txt`);
- MUST NOT передавать схему адаптеру;
- взять структуру из итогового текста ответа: последний огороженный блок кода, разбираемый как JSON, а без него — последний сбалансированный объект или массив текста, разбираемый как JSON;
- проверить структуру той же схемой.

Ответ без JSON либо не прошедший схему MUST проваливать попытку жёстким предикатом `output_schema` с текстом ошибки, так что повтор с `includeFailure` получает этот текст. Нативный структурированный вывод MUST быть главнее: при обеих возможностях схема передаётся адаптеру.

#### Scenario: Ответ JSON-блоком

- **WHEN** шаг с `output_schema` исполняется на бэкенде с `schemaFromText` без нативной схемы, а итоговый текст заканчивается блоком ```` ```json ```` с объектом, проходящим схему
- **THEN** запуск адаптера не несёт `outputSchemaPath`, промпт содержит схему, а объект записан в `output.json`

#### Scenario: Ответ не прошёл схему

- **WHEN** итоговый текст первой попытки ревьюера не содержит JSON, проходящего схему находок
- **THEN** попытка проваливается предикатом `output_schema`, а промпт второй попытки несёт текст этой ошибки

#### Scenario: Нативная схема главнее

- **WHEN** адаптер объявляет и `structuredOutput`, и `schemaFromText`, а шаг объявляет `output_schema`
- **THEN** запуск адаптера несёт `outputSchemaPath`, а промпт раздела схемы не содержит

## MODIFIED Requirements

### Requirement: Структурированный вывод по схеме

Если шаг объявляет `output_schema`, адаптер с нативным структурированным выводом SHALL получить схему и передать её бэкенду его штатным механизмом; адаптер без него, объявляющий `schemaFromText`, получает вызов без схемы, а схему держит движок по итоговому тексту. Полученный результат MUST записываться движком в `output.json` шага. Агент MUST NOT отвечать за запись этого файла.

#### Scenario: Схема передана бэкенду

- **WHEN** шаг объявляет `output_schema`, а адаптер объявляет нативный структурированный вывод
- **THEN** запуск бэкенда содержит соответствующий параметр, а результат сохраняется в `output.json`

#### Scenario: Бэкенд не поддерживает схему вывода

- **WHEN** адаптер бэкенда не объявляет ни нативного структурированного вывода, ни `schemaFromText`, а шаг объявляет `output_schema`
- **THEN** система завершается ошибкой конфигурации до начала прогона, а `burnex lint` отклоняет шаг

### Requirement: Бэкенд судьи обязан поддерживать структурированный вывод

Вызов судьи SHALL получать вердикт структурой по схеме вердикта тем же путём, что и `output_schema` шага: нативной схемой бэкенда либо, при `schemaFromText`, проверкой итогового текста движком. Адаптер, не объявляющий ни того, ни другого, MUST NOT использоваться для судьи, а несоответствие MUST обнаруживаться до начала прогона.

#### Scenario: Схема вердикта передана бэкенду

- **WHEN** предикат `judge` вычисляется на бэкенде с нативным структурированным выводом
- **THEN** запуск бэкенда содержит параметр структурированного вывода со схемой вердикта, а полученная структура сохраняется

#### Scenario: Вердикт из текста

- **WHEN** предикат `judge` вычисляется на бэкенде только с `schemaFromText`, а итоговый текст несёт JSON `{ pass, reason }`
- **THEN** промпт судьи содержит схему вердикта, а вердикт взят из этого JSON

#### Scenario: Бэкенд без структурированного вывода

- **WHEN** шаг объявляет `judge` на бэкенде, адаптер которого не объявляет ни структурированного вывода, ни `schemaFromText`
- **THEN** система завершается ошибкой конфигурации до начала прогона
