## Context

Экраны витрины объявляются строкой `src/builtin/routes.yml` и декларацией
`src/parts/ui/screens/<экран>/declaration.ts` с серверной частью; страница —
`ui/src/pages/*.tsx` на компонентах `@burnex/ui`. Вкладка Profiles
(`agent-profiles`) уже даёт форму профиля и редактор записей контекста.

## Goals / Non-Goals

**Goals:**

- Стратегию видно и можно править целиком на одном экране.
- Понятно, откуда стратегия (слой и файл) и кто её использует.
- Форма не может сохранить то, что отклонит разбор.

**Non-Goals:**

- Правка файлов, на которые стратегия ссылается (`focus: file:`, контекст).
- Правка шага пайплайна, выбирающего стратегию.
- Предпросмотр промптов участников — это видно в журнале прогона.

## Decisions

### 1. Маршрут и меню

`/review-strategies/:name?`, пункт «Review strategies» в группе `config`
после «Agents». Без имени экран открывает первую стратегию списка или
пустое состояние с действием «Create strategy».

### 2. Список

Источник — серверная часть, которая обходит оба слоя тем же разрешением,
что движок (`review-strategies`, решение 2). Элемент списка: имя, метка
слоя, число ревьюеров, режим. Одноимённая стратегия домашнего слоя,
перекрытая проектной, показана приглушённо с пометкой «перекрыта проектной»;
её можно открыть только для чтения. Файл, не прошедший разбор, остаётся в
списке с ошибкой разбора и открывается в виде текста.

### 3. Редактор

- Шапка: имя, путь файла, «используется в N шагах», кнопки Save и Delete.
- Режим — сегментированный переключатель «Independent / Defend». Поле
  `rounds` (1–5) и выбор агента защитника видны только в режиме `defend`
  (`review-defend`).
- Ревьюеры — карточки в сетке. Карточка: `id`; выбор агента комбобоксом с
  группами «Профили стратегии», «Профили настроек», «Бэкенды» и отдельным
  выбором уровня; `focus` — текст или ссылка `file:` (показывается путём).
  Последняя карточка — «Add reviewer».
- Агрегатор — выделенная карточка над ревьюерами с подписью роли: «сводит
  находки и выносит вердикт; в режиме `defend` решает спорное».
- Локальные профили — сворачиваемый блок с формой профиля из вкладки
  Profiles.
- Схема хода — строка этапов, зависящая от режима:
  `independent` — «Ревью параллельно → Агрегатор сводит → Вердикт»;
  `defend` — «Reviewers in parallel → Defend with implementer ≤ R rounds
  → Aggregator decides contested» (`review-defend`).
- Использование — список `пайплайн / работа / шаг` со ссылками на экран
  пайплайна.

### 4. Сохранение

Сервер разбирает присланный документ тем же разбором, что движок, и пишет
файл атомарно (временный файл и переименование), сохраняя комментарии и
порядок ключей, которых правка не коснулась, — тем же способом
(`yaml` `Document`), каким пишется конфигурация на экране Agents. Ошибка
разбора возвращается форме и показывается у поля по пути ключа. Удаление
стратегии, на которую ссылается хотя бы один шаг, требует подтверждения
с перечнем шагов.

## Risks / Trade-offs

- [Правка проектной стратегии из витрины меняет код проекта] → это
  ожидаемо: стратегия проекта — его код; путь файла виден в шапке, и
  правка попадает в рабочее дерево как обычное изменение.
- [Слияние комментариев YAML при перезаписи] → правка через `Document`
  сохраняет нетронутые узлы; тест на сохранение комментариев.
