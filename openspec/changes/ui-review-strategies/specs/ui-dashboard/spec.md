## ADDED Requirements

### Requirement: Экран стратегий ревью перечисляет стратегии обоих слоёв

Витрина SHALL иметь экран «Review strategies» по адресу `/review-strategies/:name?` с пунктом меню в группе `config`. Экран MUST перечислять стратегии проектного слоя `.burnex/review-strategies/` и домашнего слоя `~/.burnex/review-strategies/` с меткой слоя, числом ревьюеров и режимом. Стратегия домашнего слоя, перекрытая одноимённой проектной, MUST показываться с пометкой о перекрытии и открываться только для чтения. Файл, не прошедший разбор, MUST оставаться в списке с текстом ошибки разбора. Адрес без имени MUST открывать первую стратегию списка, а при пустом списке — пустое состояние с действием создания.

#### Scenario: Два слоя

- **WHEN** стратегия `panel` есть в проекте, а `duo` — только в домашнем слое
- **THEN** список показывает `panel` с меткой проекта и `duo` с меткой домашнего слоя

#### Scenario: Перекрытая стратегия

- **WHEN** стратегия `panel` есть в обоих слоях
- **THEN** домашняя `panel` показана с пометкой «перекрыта проектной» и без органов правки

#### Scenario: Сломанный файл

- **WHEN** файл стратегии не проходит разбор
- **THEN** он остаётся в списке с текстом ошибки и открывается как текст

### Requirement: Редактор стратегии показывает участников, режим и ход ревью

Редактор стратегии SHALL показывать путь файла, режим переключателем «Независимо / Обсуждение», лимит реплик (только в режиме обсуждения), агрегатора отдельной карточкой с подписью его роли, карточку на каждого ревьюера с `id`, агентом и `focus`, блок локальных профилей и схему хода ревью для выбранного режима. Выбор агента участника MUST предлагать профили стратегии, профили настроек и бэкенды раздельными группами и отдельно — уровень модели. `focus`, заданный `file:`, MUST показываться путём без правки содержимого файла. Редактор MUST перечислять пайплайны, работы и шаги, ссылающиеся на стратегию.

#### Scenario: Смена режима

- **WHEN** пользователь переключает режим на «Обсуждение»
- **THEN** появляется поле лимита реплик, а схема хода показывает обсуждение, консенсус и решение агрегатора без консенсуса

#### Scenario: Использование

- **WHEN** на стратегию `panel` ссылается шаг `self-improve/review/review-diff`
- **THEN** редактор `panel` показывает этот шаг ссылкой на экран пайплайна

### Requirement: Экран сохраняет стратегию в файл её слоя и проверяет её разбором

Сохранение SHALL записывать стратегию в файл слоя, из которого она пришла, атомарно и сохраняя комментарии и порядок нетронутых узлов. Новая стратегия MUST создаваться в слое, выбранном пользователем, с именем файла, равным `name`. Документ, который отклонил бы разбор движка, MUST отклоняться до записи тем же текстом, показанным у поля по пути ключа. Удаление стратегии, на которую ссылается хотя бы один шаг, MUST требовать подтверждения, называющего эти шаги.

#### Scenario: Сохранение в проектный файл

- **WHEN** пользователь меняет `focus` ревьюера проектной стратегии и сохраняет
- **THEN** меняется только этот узел файла `.burnex/review-strategies/<имя>.yml`, комментарии остаются на месте

#### Scenario: Повторный id

- **WHEN** пользователь добавляет второго ревьюера с уже занятым `id`
- **THEN** сохранение отклоняется текстом разбора у поля `id`, файл не меняется

#### Scenario: Удаление используемой стратегии

- **WHEN** пользователь удаляет стратегию, на которую ссылается шаг пайплайна
- **THEN** витрина просит подтверждения и называет этот шаг
