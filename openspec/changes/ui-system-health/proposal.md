## Why

О здоровье самой установки витрина не знает ничего. Истёкшая OAuth-сессия
бэкенда уже останавливала петлю (`backend_unauthenticated`), но след отказа
лежит только в журнале прогона. Какая версия движка крутится в демоне, есть ли
новее (`stepcast update`, `install-script-and-update`), стоит ли автозапуск
launchd (`launchd-autostart`) и для каких моделей `budget.cost` не действует
(`model-price-catalog`), можно узнать только из CLI или по файлам в
`~/.stepcast` (`docs/ui-proposals.md`, п. 2 и 3, предложение слито в один
экран «System»).

## What Changes

- **API `GET /api/system`** — строка поставки `screen-system`. Только чтение,
  ответ без сетевых обращений и без новых проб:
  - **движок**: версия из `package.json` корня движка; способ установки из
    паспорта `install.json` либо выведенный по пути, тем же
    `resolveInstallMethod`, что у `stepcast update` (битый паспорт —
    причина, а не догадка); для `managed` — ссылка, версия, время установки
    и имя каталога релиза, на который смотрит `current`;
  - **демон**: pid, время подъёма, порт, корень проекта и путь входа — от
    самого процесса демона, а не из `ui.pid`, которого у демона под launchd
    нет; признак «запущен агентом launchd»;
  - **автозапуск**: на macOS — есть ли plist, загружен ли агент, этот ли демон
    им запущен, куда смотрит путь входа агента (`current` или конкретный
    релиз). Не на macOS — `supported: false` с причиной;
  - **бэкенды**: по каждой записи `backends.<id>` действующей конфигурации —
    команда и найдена ли она на `PATH` демона, подключён ли адаптер, включён
    ли бэкенд; исход удержанной демоном пробы моделей без запуска новой;
    последний отказ бэкенда (`backend.refused`, класс `unauthenticated` или
    `rate_limit`) из журналов недавних прогонов с временем, прогоном и
    сообщением. Авторизацию демон сам не пробует: дешёвой пробы без вызова
    модели у бэкендов нет, и экран так и говорит;
  - **модели без цены**: модели, которые конфигурация называет бэкендам, не
    сообщающим цену (`default_model`, `model_tiers`, `defaults.model`), и
    которых нет в каталоге цен, плюс бэкенды без названной модели — тем же
    правилом, что предупреждение прогона `budget.cost_unpriced`; дата каталога.
- **API `GET /api/system/update`** — проверка доступного обновления по тому
  же способу установки и тем же правилам, что и `stepcast update`: `managed` —
  последний тег `vX.Y.Z` против установленного, `checkout` — отставание ветки
  от вышестоящей, `npm` — `latest` реестра против версии пакета. Сетевой
  вызов с пределом, исход удерживается демоном; `?refresh=1` проверяет заново.
- **API `POST /api/system/update`** — кнопка «Обновить»: демон порождает
  отсоединённый `stepcast update` из своего корня проекта с выводом в
  `~/.stepcast/update.log`. Обновление и перезапуск демона делает сама
  команда — тот же путь, что и в терминале; витрина ждёт возвращения демона
  и показывает хвост журнала, если он не вернулся.
- **API `POST /api/system/autostart`** — переключатель «запускать при входе»:
  `{ "enabled": true }` порождает отсоединённый `stepcast up --install`,
  `false` — `stepcast down --uninstall`, затем `stepcast up`, оба — в корне
  проекта демона. Вне macOS — отказ `409` с причиной, без порождения
  процессов.
- **Экран «System»** — `ui/src/pages/System.tsx`, `ui/src/screens/system.tsx`:
  карточки «Engine», «Daemon», «Autostart», «Update», таблица «Backends» и
  список «Models without price».
- **Маршрут** `screen-system` на `/system`, `nav: { group: system, order: 10 }`.
- **Общие функции вместо копий**: проверка доступного обновления выносится из
  `runUpdateCommand` в чистую функцию рядом с `planUpdate`; правило
  «вызов без цены» — из `warnAboutUnpricedCalls` раннера в общий предикат.
  Тексты CLI не меняются.
- **Тесты** на API, на порождение команд обслуживания (подменой), на
  разметку экрана и ожидания таблицы маршрутов.
- **Документация**: раздел «Экран System» в `docs/release.md` — что показано,
  откуда берётся, как работают «Обновить» и переключатель автозапуска.

### Modified Capabilities

- `ui-dashboard`: экран и API «System» — движок, демон, автозапуск, доступное
  обновление, бэкенды, модели без цены; действия «Обновить» и «запускать при
  входе».
- `ui-daemon`: демон сообщает о себе сам (pid, время подъёма, путь входа,
  запуск агентом launchd) и переживает собственный перезапуск, порождённый
  витриной.

## Impact

- Код: `src/parts/ui/system.ts` (свёртка ответа), `src/parts/ui/screens/system/{declaration,server}.ts`,
  `src/parts/ui/rows.ts`, `src/builtin/routes.yml`;
  `src/parts/install/plan.ts` и `commands/update.ts` (общая проверка
  обновления); `src/parts/ui/daemon/launchd.ts` (чтение состояния агента —
  `launchctl print` с выводом); `src/parts/ui/daemon/server.ts` (сведения о
  самом демоне и внедряемый пуск команд обслуживания, как `launchRun`);
  `src/parts/pipeline/run/runner.ts` и `budget/priceCatalog.ts` (общий
  предикат «без цены»); `ui/src/pages/System.tsx`, `ui/src/screens/system.tsx`,
  `ui/src/screens/index.ts`, `ui/src/api.ts`.
- API: новые `GET /api/system`, `GET /api/system/update`,
  `POST /api/system/update`, `POST /api/system/autostart`,
  `GET /api/system/log` (хвост журнала действия). Изменяющие маршруты
  под той же проверкой своего происхождения (`sameOrigin`), что и прочие.
- Побочные эффекты: «Обновить» и переключатель перезапускают демон — витрина
  на секунды недоступна. Проверка обновления ходит в сеть (`git ls-remote`,
  `npm view`) только по явному запросу экрана.
- Зависимостей не добавляется.
