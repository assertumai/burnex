## ADDED Requirements

### Requirement: Экран «System» показывает состояние установки без сети и без новых проб
Витрина SHALL отдавать `GET /api/system` и экран «System» по маршруту `/system` в группе меню `system`: версию движка и способ установки (для `managed` — ссылку, версию и релиз, на который смотрит `current`), pid, время подъёма, порт, корень проекта и путь входа демона, состояние автозапуска, по каждому бэкенду действующей конфигурации — команду и найдена ли она, подключён ли адаптер, удержанный исход пробы моделей и последний отказ бэкенда из журналов прогонов, а также модели без цены. Ответ MUST NOT порождать сетевых обращений и новых проб бэкендов.

#### Scenario: Версия и способ установки
- **WHEN** паспорт установки называет `managed` с ссылкой `v0.4.0`, а `current` указывает на релиз `0.4.0`
- **THEN** ответ содержит версию из `package.json` движка, способ `managed`, ссылку `v0.4.0` и имя релиза `0.4.0`

#### Scenario: Способ установки не определяется
- **WHEN** движок лежит в каталоге релизов, а паспорта установки нет
- **THEN** ответ содержит причину словами `resolveInstallMethod`, а кнопка «Обновить» неактивна с этой причиной

#### Scenario: Сведения о демоне от самого процесса
- **WHEN** демон поднят агентом launchd и записи `ui.pid` нет
- **THEN** ответ содержит pid и время подъёма этого процесса и признак «запущен агентом launchd»

#### Scenario: Команда бэкенда не найдена
- **WHEN** `backends.codex.command` называет команду, которой нет ни по пути, ни в каталогах `PATH` окружения шага
- **THEN** строка `codex` имеет состояние команды `missing`, а удержанной пробы нет — `not-probed`

#### Scenario: Последний отказ аутентификации виден на экране
- **WHEN** в одном из 20 новейших прогонов проекта есть событие `backend.refused` класса `unauthenticated`, а сводка расхода прогона называет бэкенд попытки `claude`
- **THEN** строка `claude` содержит этот отказ с временем, прогоном, шагом и сообщением бэкенда

#### Scenario: Бэкенд отказа не установлен
- **WHEN** у события `backend.refused` нет попытки с тем же шагом в сводке расхода прогона
- **THEN** отказ показан отдельной строкой без бэкенда и не приписан ни одному бэкенду

#### Scenario: Модель без цены
- **WHEN** бэкенд не сообщает цену, а `backends.<id>.model_tiers.fast` называет модель, которой нет в каталоге цен
- **THEN** перечень моделей без цены содержит бэкенд, модель и путь `backends.<id>.model_tiers.fast`, рядом — дата каталога

#### Scenario: Модель в каталоге не попадает в перечень
- **WHEN** бэкенд не сообщает цену, а названная модель есть в каталоге, либо бэкенд цену сообщает
- **THEN** перечень моделей без цены этой пары не содержит

#### Scenario: Пункт меню
- **WHEN** пользователь открывает витрину со встроенной таблицей маршрутов
- **THEN** в группе `system` есть пункт «System», ведущий на `/system`

### Requirement: Доступное обновление проверяется тем же правилом, что и `stepcast update`
Витрина SHALL отдавать `GET /api/system/update` с исходом `available`, `up-to-date`, `blocked`, `no-tags` или `unknown`, вычисленным той же функцией, которой `stepcast update` решает «обновлять нечего», по способу установки из паспорта или выведенному по пути. Сетевая проверка MUST идти только по этому маршруту, с пределом времени, и её исход MUST удерживаться демоном, пока `?refresh=1` не потребует проверить заново.

#### Scenario: Новый тег у установки managed
- **WHEN** установка `managed` стоит на `v0.4.0`, а `git ls-remote` репозитория из паспорта даёт тег `v0.5.0`
- **THEN** исход — `available` с текущей `v0.4.0` и последней `v0.5.0`

#### Scenario: Установлен последний тег
- **WHEN** установка `managed` стоит ровно на последнем строгом теге
- **THEN** исход — `up-to-date`, и `stepcast update` при тех же данных печатает «обновлять нечего»

#### Scenario: Чекаут с незакоммиченными правками
- **WHEN** установка `checkout`, а `git status --porcelain` непуст
- **THEN** исход — `blocked` с той же причиной, с какой откажет `stepcast update`, и кнопка «Обновить» неактивна

#### Scenario: Сеть недоступна
- **WHEN** команда проверки не ответила за предел или завершилась отказом
- **THEN** исход — `unknown` с причиной, ответ приходит не позже предела, общего на всю проверку, а пока проверка ждёт сеть, демон отвечает на другие запросы

### Requirement: «Обновить» и переключатель автозапуска исполняются командами CLI
`POST /api/system/update` SHALL порождать отсоединённый `stepcast update`, а `POST /api/system/autostart` с `enabled: true` — `stepcast up --install`, с `enabled: false` — `stepcast down --uninstall` и затем `stepcast up`; рабочий каталог — корень проекта демона, вывод — в журнал действия под `~/.stepcast`. Ответ MUST быть `202` с путём журнала; пока порождённый демоном процесс обслуживания жив, повторный запрос любого из двух маршрутов MUST отвечать `409`. Оба маршрута MUST отвергать запрос не со своей страницы.

#### Scenario: Кнопка «Обновить»
- **WHEN** экран отправляет `POST /api/system/update`
- **THEN** порождается отсоединённый процесс `stepcast update` той же точки входа в корне проекта демона, ответ — `202` с путём `update.log`

#### Scenario: Включить автозапуск
- **WHEN** на macOS экран отправляет `POST /api/system/autostart` с `{ "enabled": true }`
- **THEN** порождается отсоединённый `stepcast up --install` в корне проекта демона

#### Scenario: Выключить автозапуск
- **WHEN** на macOS экран отправляет `POST /api/system/autostart` с `{ "enabled": false }`
- **THEN** порождается отсоединённый процесс, выполняющий `stepcast down --uninstall`, а затем `stepcast up` в корне проекта демона

#### Scenario: Автозапуск вне macOS
- **WHEN** демон работает не на macOS и приходит `POST /api/system/autostart`
- **THEN** ответ — `409` с причиной «работает только на macOS», процесс не порождается, а экран показывает переключатель неактивным с этой причиной

#### Scenario: Действие уже идёт
- **WHEN** порождённый ранее процесс обслуживания ещё жив и приходит новый `POST` на обновление или автозапуск
- **THEN** ответ — `409`, второй процесс не порождается

#### Scenario: Запрос с чужой страницы
- **WHEN** `POST /api/system/update` приходит с заголовком `Origin` чужого сайта
- **THEN** запрос отвергнут, процесс не порождается

#### Scenario: Действие кончилось без перезапуска
- **WHEN** после `202` прежний демон отвечает, а порождённый им процесс обслуживания уже завершился («обновлять нечего», отказ, сбой)
- **THEN** `GET /api/system/log` несёт исход процесса с кодом выхода, и экран сразу показывает этот исход с хвостом журнала, не дожидаясь 60 секунд

#### Scenario: Демон не вернулся
- **WHEN** после `202` демон с новым pid не отвечает на `GET /api/system` 60 секунд
- **THEN** экран показывает хвост журнала действия из `GET /api/system/log` и команду, которой повторить действие в терминале
