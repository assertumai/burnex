## Context

Экран «Review strategies» уже умеет всё нужное для документа стратегии:
слои, перекрытие, разбор движком с путём ключа, запись через `yaml`
`Document` с проверкой до подмены, удаление с предупреждением об
использовании. Стратегия обсуждения отличается только схемой
(`DiscussionStrategySchema`), каталогом (`discussion-strategies`) и тем, какие
шаги её используют (`discuss:`).

## Goals / Non-Goals

**Goals:** экран правки стратегий обсуждения тем же поведением, что у
стратегий ревью; без второй копии чтения, записи и каркаса страницы.

**Non-Goals:** правка файлов `file:` из формы (как и у ревью); правка
`step_agents`; предпросмотр промптов.

## Decisions

### 1. Общий серверный модуль по виду стратегии

`src/parts/ui/strategies.ts` — `readStrategies`, `saveStrategy`,
`deleteStrategy` с параметром `StrategyKind`: каталоги слоёв, загрузка
движком (`loadReviewStrategy` / новая `loadDiscussionStrategy`), схема для
пути лишнего ключа корня и выбор ссылки шага в `PipelineView`. Прежние
`readReviewStrategies` и др. остаются тонкими обёртками — тесты и маршруты
ревью не меняются.

### 2. Использование по шагам `discuss:`

`PipelineStepView` получает `discussStrategy` — ссылку шага `discuss:` без
отпечатка, как `reviewStrategy`. «Used by» сравнивает настоящий путь файла.

### 3. API

`GET|PUT|DELETE /api/discussion-strategies` — те же тела и коды, что у
`/api/review-strategies`.

### 4. Витрина: общий каркас и свой редактор

Список, шапка, выбор слоя, кнопки, состояние страницы и запросы выносятся в
обобщённый `StrategiesScreen` с описанием вида: заголовок, подпись списка,
черновик ↔ документ, редактор. «Review strategies» становится его
применением без изменения поведения; общие поля (`Field`, `ParticipantFields`,
`TextOrFile`, локальные профили) переиспользуются.

Редактор обсуждения: раунды (1–5; `rounds` не пишется в файл, пока равен
умолчанию 1 и его не было), схема хода, автор, агрегатор, участники, профили.
`id` участников `author` и `aggregator` разбор движка отклоняет — форма
показывает его текст у поля.

## Risks / Trade-offs

- **[Рефакторинг экрана ревью]** → его тесты витрины и маршрутов остаются как
  есть и обязаны проходить.
