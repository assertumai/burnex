## Why

Петлю саморазвития сегодня запускают руками, по одному заходу: человек
пересобирает движок, зовёт `stepcast run .stepcast/pipelines/self-improve.yml`,
смотрит, свелось ли что-нибудь, и повторяет. Burnex гоняет ту же петлю скриптом
(`docs/burnex-after-stepcast.md`, раздел 5 «Автономная петля»): перед каждой
итерацией движок собирается из `HEAD` в отдельном worktree, а петля
останавливается по трём понятным условиям. Прежние скрипты петли
(`scripts/merge-lanes.mjs`, `scripts/finalize.mjs`) заглушены изменением
`drop-superseded-loop-scripts`, поэтому новый скрипт обязан звать только команды
движка, а не их.

Одного скрипта для признака «грязная копия петлю не останавливает» мало.
Головной шаг пайплайна (`guard-clean-tree` в `.stepcast/jobs/slots.yml`) отказывает
на грязном дереве, и такая итерация не коммитит ничего, а это условие остановки.
Проверка чистоты защищает одно место — сведение, которое накладывает дорожки на
дерево проекта (дорожки идут в worktree от `HEAD` и незакоммиченного не видят по
требованию «Режим worktree изолирует работу от текущего дерева»). Режим
`merge-lanes --onto <ветка>` (изменение `merge-lanes-onto-branch-tip`) эту защиту
уже несёт сам: на копии, грязной вне файлов очереди, сведение ждёт без ошибки, а не
накладывается поверх. Перевод пайплайна на `--onto` то изменение оставило решению
владельца, потому что имя ветки знает тот, кто запускает петлю. Скрипт это имя
знает: это ветка копии, из которой его запустили.

## What Changes

- Новый скрипт `scripts/self-improve-loop.sh` (bash, рядом с
  `scripts/release-local.sh`). Он гоняет `.stepcast/pipelines/self-improve.yml`
  итерация за итерацией в копии, из которой запущен, и сводит каждую итерацию на
  ветку этой копии.
  - Перед каждой итерацией движок собирается из вершины ветки (коммит
    `refs/heads/<ветка>`, а не рабочее дерево) в отдельном постоянном worktree.
    `npm ci` в нём выполняется, только когда `package-lock.json` отличается от того,
    с которым ставились зависимости в прошлый раз (или зависимостей ещё нет).
    `npm run build` выполняется на каждой итерации.
  - Прогон зовётся собранным `bin.js` из этого worktree с входом
    `--input onto=<ветка>`. Скрипт зовёт только `git`, `npm` и команды движка,
    файлы `scripts/*.mjs` — никогда.
  - Петля останавливается в трёх случаях: итерация не сдвинула вершину ветки
    (прогон ничего не закоммитил); упала сборка (`npm ci` или `npm run build`);
    выполнено `MAX_RUNS` итераций (переменная окружения, по умолчанию 20). Каждая
    остановка печатает свою причину и выходит своим кодом.
  - Грязная рабочая копия петлю не останавливает. Скрипт её не проверяет,
    движок собирается из коммита, а пайплайн с входом `onto` чистоты не требует.
- Пайплайн `self-improve.yml` получает вход `onto` (имя ветки, по умолчанию пустая
  строка). Работы `slots` и `merge` получают его параметром с места подключения.
  - С непустым `onto` шаг `guard-clean-tree` пропускает проверку, а `merge-lanes`
    зовётся с `--onto <ветка>` и ждёт чистой копии сам.
  - С пустым `onto` (ручной заход `stepcast run` без ключей, доска витрины) поведение
    прежнее байт в байт: проверка чистоты на месте, сведение без `--onto`.
- `docs/backlog.md` получает раздел об автономной петле: запуск (в том числе
  `caffeinate -i` на macOS), переменные, условия остановки и коды выхода, почему
  грязная копия петлю не останавливает, где лежит worktree движка.

### Modified Capabilities

- `self-improvement-loop`: появляются автономный запуск петли скриптом с
  объявленными условиями остановки и вход пайплайна `onto`. Этот вход переводит
  сведение на вершину ветки и снимает требование чистой копии.

## Impact

- `scripts/self-improve-loop.sh`: новый файл.
- `.stepcast/pipelines/self-improve.yml`: вход `onto` и его передача в `slots` и
  `merge`.
- `.stepcast/jobs/slots.yml`: параметр `onto`, условный пропуск проверки чистоты.
- `.stepcast/jobs/merge.yml`: параметр `onto`, условный ключ `--onto`.
- `docs/backlog.md`: раздел «Автономная петля».
- `test/`: тест скрипта на одноразовом репозитории с поддельным движком, тест
  передачи `onto` в пайплайне.
- Код движка (`src/`) не меняется: `merge-lanes --onto`, `assert-clean`,
  `run --input` уже есть.
