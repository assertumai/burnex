## ADDED Requirements

### Requirement: Защитник форкается только из дерева имплементатора

Форк сессии имплементатора в режиме `defend` SHALL допускаться, только если работа шага имплементатора и работа шага `review` исполняются в одном рабочем дереве. Иначе защитник MUST быть свежим агентом с причиной `other_tree`, записанной в журнал. Линт MUST предупреждать, если дерево работы имплементатора статически отличается от дерева работы шага `review`: в том числе когда у работы имплементатора личное дерево, а при `scope: job` — когда имплементатор принадлежит другой работе.

#### Scenario: Имплементатор в другом дереве

- **WHEN** шаг `review` объявляет `implementer: build.implement`, работа `build` объявляет `tree: b`, а работа шага `review` исполняется в дереве по умолчанию
- **THEN** защитник — свежий агент, а журнал записывает `mode: fresh` и `reason: other_tree`
- **AND** линт выдаёт предупреждение с путём `jobs.<id>.steps.<n>.implementer`

#### Scenario: Имплементатор в том же дереве другой работы

- **WHEN** шаг `review` объявляет `implementer: build.implement`, у работы `build` два потомка, и все работы в дереве по умолчанию
- **THEN** защитник — форк сессии имплементатора
