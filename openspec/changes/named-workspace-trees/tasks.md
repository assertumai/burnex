## 1. Документ и схема

- [ ] 1.1 Схема документа: `workspace.trees` (только пайплайн, слаги, без `own` и повторов) и `workspace.tree` (работа); `schema/pipeline.schema.json`, `schema/job.schema.json`
- [ ] 1.2 Разрешение дерева работы при раскрытии: умолчание — первое из `trees`, `own` при переопределённом режиме; дерево входит в раскрытый пайплайн, но не в ключ шага
- [ ] 1.3 Голова дерева: вычисление по графу (единственная работа, от которой транзитивно зависят остальные работы дерева)

## 2. Линт

- [ ] 2.1 Ошибки: неизвестное дерево, `trees` у работы, `trees`/`tree` в `cwd`, `tree` при переопределённом режиме, две головы, `inherit` у не-головы
- [ ] 2.2 Ошибка `inherit` при нескольких зависимостях — только у головы именованного дерева
- [ ] 2.3 Предупреждение о паре независимых работ одного дерева с порядком исполнения
- [ ] 2.4 `session_group`: работы группы в одном дереве (замена правила «Рабочее дерево»)
- [ ] 2.5 Предупреждение `implementer` из другого дерева (`own` у работы имплементатора)

## 3. Рабочие деревья

- [ ] 3.1 `run/workspace.ts`: дерево по умолчанию заводится до первой работы от исходного состояния; каталоги `<base>/trees/<tree>/` и `<base>/jobs/<job>/`
- [ ] 3.2 Именованное дерево и `own` заводятся при старте головы и засеваются якорем источника (прежний механизм засева развилки)
- [ ] 3.3 Убрать выбор каталога по форме графа (`continue` для цепочки, засев развилки); продолжение — по принадлежности дереву
- [ ] 3.4 Вложенные репозитории (`project.nested_repos`), `source: commit` и `live_files` — на дерево, а не на работу
- [ ] 3.5 `gc` и `apply` берут каталог из записи работы; проверить, что раскладку они не выводят

## 4. Планировщик

- [ ] 4.1 Занятость дерева в `runner.ts`: готовая работа ждёт свободного дерева, первой идёт объявленная раньше
- [ ] 4.2 Проверка: независимые работы одного дерева при `concurrency: 2` идут по очереди, работы разных деревьев — параллельно

## 5. Журнал и возобновление

- [ ] 5.1 Поле `tree` в записи работы, `inherited_from` у головы, `continued` у остальных; версия формата журнала; чтение прежних записей
- [ ] 5.2 `resume`: каталог дерева перенимается из исходного прогона, если переиспользованы все его работы до первой переисполняемой; иначе дерево заводится заново, и переиспользованные работы дерева после точки расхождения переисполняются

## 6. Сессии

- [ ] 6.1 `defenderChoice`: форк только при совпадении дерева работы имплементатора и работы `review`; иначе свежий с причиной `other_tree`; схема журнала `defense.ndjson` и витрина знают новую причину
- [ ] 6.2 Проверка: форк из той же работы, из другой работы того же дерева (развилка), свежий из другого дерева
