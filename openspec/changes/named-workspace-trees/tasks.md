## 1. Документ и схема

- [x] 1.1 Схема документа:
  - `workspace.scope` — `run | job`, только у пайплайна;
  - `workspace.trees` — только у пайплайна, слаги, без `own` и повторов;
  - `workspace.tree` — у работы;
  - обновить `schema/pipeline.schema.json` и `schema/job.schema.json`.
- [x] 1.2 Разрешение дерева работы при раскрытии:
  - умолчание — первое из `trees`;
  - `own` при переопределённом режиме и при `scope: job`;
  - дерево входит в раскрытый пайплайн, но не в ключ шага.
- [x] 1.3 Вычисление головы дерева по графу: единственная работа, от которой транзитивно зависят остальные работы дерева.

## 2. Линт

- [x] 2.1 Ошибки области и деревьев по требованию «Статическая валидация проверяет область и деревья».
- [x] 2.2 `inherit` при нескольких зависимостях обязателен только у работ, которым заводится каталог.
- [x] 2.3 Предупреждение о паре независимых работ одного дерева с порядком исполнения.
- [x] 2.4 `session_group`: одно дерево, ошибка при `scope: job` (замена правила «Рабочее дерево»).
- [x] 2.5 Предупреждение: `implementer` из другого дерева.

## 3. Рабочие каталоги

- [x] 3.1 `run/workspace.ts`:
  - дерево по умолчанию заводится до первой работы от исходного состояния;
  - раскладка `<base>/trees/<tree>/` и `<base>/jobs/<job>/`.
- [x] 3.2 Засев полным переносом каталога источника:
  - `copy`: копия целиком, клонирование файлов там, где ФС умеет;
  - `worktree`: `git worktree add --detach` на коммит якоря источника и содержимое источника поверх, кроме `.git`;
  - вложенные репозитории переносятся так же;
  - отступление к засеву якорем, если каталога источника нет.
- [x] 3.3 Засев в момент завершения источника, до передачи его дерева следующей работе; каталог пропущенной головы снимается.
- [x] 3.4 Убрать выбор каталога по форме графа (продолжение цепочки, засев развилки).
- [x] 3.5 `source: commit` и `live_files` — на дерево, а не на работу.
- [x] 3.6 Убедиться, что `gc`, `apply` и `merge-lanes` берут каталог из записи работы и раскладку не выводят.

## 4. Планировщик

- [x] 4.1 Занятость дерева в `runner.ts`: готовая работа ждёт свободного дерева, первой идёт объявленная раньше.
- [x] 4.2 Проверка при `concurrency: 2`:
  - независимые работы одного дерева идут по очереди;
  - работы разных деревьев идут параллельно;
  - при `scope: job` параллельность как прежде.

## 5. Журнал и возобновление

- [x] 5.1 Запись работы:
  - поле `tree`;
  - `seed { from, by, reason }`;
  - `continued`;
  - `inherited_from` заменяется на `seed.from`;
  - поднять версию формата журнала и читать прежние записи.
- [x] 5.2 `resume` по деревьям:
  - перенять каталог дерева или завести заново от источника;
  - привести к якорю последнего переиспользованного шага дерева;
  - игнорируемое не трогать.
- [x] 5.3 Проверка: в общем дереве игнорируемые следы поздних работ остаются, а отслеживаемое восстановлено.

## 6. Сессии

- [x] 6.1 `defenderChoice`: форк только при совпадении деревьев, иначе свежий защитник с причиной `other_tree`; схема `defense.ndjson` и витрина знают новую причину.
- [x] 6.2 Проверка форка защитника в трёх случаях:
  - из той же работы;
  - из другой работы того же дерева (развилка);
  - свежий защитник из другого дерева.
