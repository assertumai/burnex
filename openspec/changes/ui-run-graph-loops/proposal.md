## Why

Группа работ с `loops` (`job-group-loops`) исполняется проходами: движок пишет
в `status.json` запись цикла (`loops[]`: `iterations`, `max_iterations`,
`verdict`, `status`), а шаги каждого прохода кладёт в свой каталог
`jobs/<job>/steps/pass-<n>/`. Витрина не читает ни того, ни другого: граф
прогона рисует участника цикла одним узлом без числа проходов, а вывод шага
(`/api/step-output`) всегда берёт последний проход — вывод прошлых проходов
лежит на диске, но в интерфейсе недостижим. Сколько проходов было, на каком
цикл сейчас и чем кончился, видно только в `status.json` и журнале событий
(`docs/ui-proposals.md`, п. 2, строка «`loops` на работе»).

## What Changes

- Снимок прогона (`src/parts/ui/snapshot.ts`) несёт у работы-участника цикла
  поле `loop`: идентификатор цикла, число начатых проходов, предел, текущий
  проход (у идущего цикла), вердикт и статус цикла — из записи
  `status.json` — и перечень проходов, чьи каталоги шагов этой работы есть на
  диске. У работы вне цикла поля нет.
- Раскладка графа (`src/parts/ui/graph.ts`) принимает и отдаёт это же в узле;
  узел графа на странице прогона показывает метку прохода: «проход n из
  max» у идущего цикла, число проходов и вердикт у законченного.
- Вывод шага (`/api/step-output`, `readStepOutput`) принимает параметр `pass`
  и читает каталог шага этого прохода; ответ называет проход, который
  прочитан. Без параметра — как сейчас, последний проход. Неверный `pass` —
  `400`, прохода без каталога — пустой ответ, как у шага без каталога.
- Карточка работы-участника цикла на странице прогона получает переключатель
  проходов; выбранный проход передаётся выводу каждого шага работы.
  Переключатель попыток шага (`attempts`) остаётся как есть и действует
  внутри выбранного прохода.
- Тесты снимка, раскладки графа, маршрута вывода шага и разметки узла и
  карточки.

Вне изменения: опубликованный выход работы (`artifacts/<job>.json`) прошлых
проходов движок стирает перед следующим проходом (`resetLoopParticipants`) —
витрина его не восстанавливает и по-прежнему показывает выход последнего
прохода. Список файлов шага в снимке (`prompt.txt`, `output.json`, …) тоже
остаётся списком последнего прохода. Граф на экране «Pipelines» (по
определению, без прогона) не меняется.

### Modified Capabilities

- `ui-dashboard`: новое требование — участник цикла по группе работ показывает
  на графе прогона число проходов и текущий проход, а вывод его шагов

## Impact

- Код демона: `src/parts/ui/snapshot.ts`, `src/parts/ui/graph.ts`,
  `src/parts/ui/stepOutput.ts`, `src/parts/ui/screens/run/server.ts`.
  Чтение — через существующие `readStatus`/`LoopRecordSchema`,
  `findStepDir(..., loopPass)` и `parsePassDirName`; движок и формат журнала
  не меняются.
- Браузер: `ui/src/api.ts` (зеркала типов и параметр `pass` у
  `fetchStepOutput`), `ui/src/components/JobGraph.tsx`,
  `ui/src/components/StepOutput.tsx`, `ui/src/pages/RunDetail.tsx`, стили.
- API: `/api/step-output` получает необязательный параметр `pass`; ответ —
  необязательное поле `pass`. Обратно совместимо.
- Тесты: `test/ui-snapshot.test.ts`, `test/ui-graph.test.ts`,
  `test/ui-server.test.ts` (или тест маршрута вывода шага), тест разметки в
  `ui/test/`.
- Документация: `docs/ui-proposals.md` — строка «`loops` на работе» отмечается
  сделанной в `ui-run-graph-loops`.
