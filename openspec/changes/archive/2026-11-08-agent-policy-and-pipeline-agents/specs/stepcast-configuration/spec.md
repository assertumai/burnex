## ADDED Requirements

### Requirement: Ключи `pipeline_agents` и `step_agents` задают выбор пользователя по пайплайну и по шагу
Конфигурация SHALL принимать ключ `pipeline_agents.<имя пайплайна>` и ключ `step_agents.<имя пайплайна>.<работа>.<шаг>`, где значение — запись с необязательными полями `agent`, `model`, `model_tier`, `effort` и хотя бы одним из них. Имя пайплайна — поле `name` его документа, работа — идентификатор в карте `jobs:` документа до раскрытия дорожек, шаг — `id` шага. Запись, объявившая одновременно `model` и `model_tier`, и запись с неизвестным полем отклоняются разбором конфигурации с указанием файла и пути ключа. Оба ключа допустимы в глобальном и в проектном файле и сливаются между слоями по листьям.

#### Scenario: Запись пайплайна принимается
- **WHEN** `~/.stepcast/config.yml` содержит `pipeline_agents: { self-improve: { agent: codex, model_tier: deep } }`
- **THEN** конфигурация разрешается без ошибки, и отчёт `stepcast config` называет этот файл источником `pipeline_agents.self-improve.agent`

#### Scenario: Модель и tier в одной записи
- **WHEN** запись `step_agents.p.implement.code` объявляет и `model: sonnet`, и `model_tier: fast`
- **THEN** разбор конфигурации отклоняется с указанием файла и пути `step_agents.p.implement.code`

#### Scenario: Проектный файл перекрывает поле глобальной записи
- **WHEN** глобальный файл объявляет `pipeline_agents.p: { agent: codex, effort: high }`, а проектный — `pipeline_agents.p: { agent: claude }`
- **THEN** действующая запись — `{ agent: claude, effort: high }`, у `agent` источник — проектный файл, у `effort` — глобальный

### Requirement: Политика `agent_policy` выбирает, кто сильнее — документ или пользователь
Конфигурация SHALL принимать ключ верхнего уровня `agent_policy` со значением `force` или `fallback` и SHALL считать его равным `force`, когда он не объявлен ни одним слоем. Ключ допустим в обоих файлах, и ближний слой побеждает. Порядок слоёв, который задаёт каждое значение, определяет требование «Ранг выбора пользователя задаётся политикой `agent_policy`» возможности `pipeline-definition`.

#### Scenario: Умолчание
- **WHEN** ни один файл не объявляет `agent_policy`
- **THEN** отчёт `stepcast config` показывает `agent_policy` равной `force` со встроенным умолчанием в качестве источника

#### Scenario: Неизвестное значение
- **WHEN** файл объявляет `agent_policy: always`
- **THEN** разбор конфигурации отклоняется с указанием файла и ключа `agent_policy`

### Requirement: Запись выбора пользователя не роняет чужие пайплайны
Движок SHALL считать предупреждением, а не ошибкой, запись `step_agents`, которая называет работу или шаг, отсутствующие в пайплайне, или шаг не агентского вида. Запись `pipeline_agents` или `step_agents`, чей `agent` не назван среди бэкендов, SHALL отклонять раскрытие только того пайплайна, к которому запись относится, с указанием файла и пути ключа.

#### Scenario: Запись исчезнувшего шага
- **WHEN** `step_agents.p.old.gone` объявлена, а в пайплайне `p` нет работы `old`
- **THEN** `stepcast run` пайплайна `p` исполняется, а `stepcast config --pipeline` называет запись в списке записей без действия с причиной «шага нет в пайплайне»

#### Scenario: Неизвестный агент в записи другого пайплайна
- **WHEN** `pipeline_agents.other` объявляет `agent: nosuch`, а запускается пайплайн `p`
- **THEN** раскрытие пайплайна `p` проходит без ошибки

#### Scenario: Неизвестный агент в записи своего пайплайна
- **WHEN** `pipeline_agents.p` объявляет `agent: nosuch`, а запускается пайплайн `p`
- **THEN** раскрытие отклоняется с указанием файла конфигурации и пути `pipeline_agents.p.agent`

### Requirement: `stepcast config --pipeline` показывает итоговый выбор и его источник
Команда `stepcast config --pipeline <p>` SHALL раскрыть пайплайн `<p>` (путь к файлу или `stepcast:<имя>`) с действующей конфигурацией и вывести вслед за обычным отчётом действующую политику с её источником и, для каждого агентского шага, агента, модель и effort вместе с источником каждого. Обязательные входы без умолчаний подставляются заглушками. Отброшенная чужая модель выводится вместе со слоем, из которого пришла. Отдельным списком выводятся записи `pipeline_agents` и `step_agents` этого пайплайна, которые не повлияли ни на один шаг, с причиной: проиграли документу при названной политике либо называют отсутствующий шаг.

#### Scenario: Источник у каждого значения
- **WHEN** при `agent_policy: fallback` агента шага `implement/code` дал `pipeline_agents.p`, а модель — `step_agents.p.implement.code`
- **THEN** строка шага `implement/code` называет агента с источником `pipeline_agents` и файлом и модель с источником `step_agents` и файлом

#### Scenario: Проигравшая запись названа
- **WHEN** при `agent_policy: force` запись `step_agents.p.review.check` объявляет `model: sonnet`, а шаг `review/check` объявляет `model: opus`
- **THEN** запись перечислена среди записей без действия с причиной «проиграла шагу (политика force)»

#### Scenario: Поставляемый пайплайн
- **WHEN** выполняется `stepcast config --pipeline stepcast:self-improve` в проекте без файла этого пайплайна
- **THEN** команда раскрывает поставляемый пайплайн и выводит его агентские шаги

### Requirement: Экран Pipelines записывает выбор пользователя в глобальный файл
Экран Pipelines SHALL позволять выбрать для пайплайна и для его агентского шага агента, модель или tier и effort, а также снять выбор, и SHALL записывать результат в `pipeline_agents` или `step_agents` файла `~/.stepcast/config.yml`, сохраняя комментарии, проверяя результат схемой конфигурации и подменяя файл атомарно. Выбор tier снимает `model` той же записи, выбор модели снимает `model_tier`. Опустевшая запись удаляется вместе с опустевшими родительскими ключами. После записи экран показывает заново раскрытый пайплайн, действующую политику и отметку у записи, которая не влияет на шаг: проигрывает документу либо перекрыта проектным файлом.

#### Scenario: Выбор модели для шага
- **WHEN** пользователь на карточке шага `implement/code` пайплайна `p` выбирает модель `sonnet`
- **THEN** `~/.stepcast/config.yml` содержит `step_agents.p.implement.code.model: sonnet`, прежние комментарии файла сохранены, а карточка показывает модель шага с источником `step_agents`

#### Scenario: Снятие выбора
- **WHEN** пользователь снимает единственное поле записи `step_agents.p.implement.code`
- **THEN** в файле не остаётся ни этой записи, ни опустевших `step_agents.p.implement` и `step_agents.p`

#### Scenario: Запись без действия помечена
- **WHEN** при `agent_policy: force` пользователь выбирает модель для шага, объявившего `model` сам
- **THEN** запись сохраняется, а карточка шага помечает её как проигрывающую документу и показывает прежнюю модель шага
