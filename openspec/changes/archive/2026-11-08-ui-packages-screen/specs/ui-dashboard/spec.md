## ADDED Requirements

### Requirement: Экран «Packages» перечисляет пакеты обоих слоёв с их составом
Витрина SHALL отдавать экран «Packages» по маршруту `/packages` в группе меню `extend`, который по слоям «Project» и «Home» перечисляет найденные каталоги пакетов: имя, `package_version`, описание, путь каталога, статус (действует, сломан с причиной, затенён пакетом проекта), незакрытые `needs` и состав поимённо по видам — пайплайны, шаги, скрипты, плагины, виджеты, дашборды, маршруты. Сводка пакета в `GET /api/packages` MUST нести состав полем `contents` и совпадать с элементом `stepcast package list --json` того же пакета.

#### Scenario: Состав исправного пакета
- **WHEN** в слое проекта лежит пакет `hello` с `pipelines/greet.yml`, `steps/lint/step.yml`, `widgets/clock.tsx`, `dashboards/ops.yml` и `routes.yml` со строкой `id: pkg-ops`
- **THEN** экран в секции «Project» показывает `hello` со статусом «действует», путём каталога и составом: пайплайн `hello:greet`, шаг `lint`, виджет `clock`, дашборд `ops`, маршрут `pkg-ops`

#### Scenario: Сломанный пакет
- **WHEN** `package.yml` пакета не разбирается как YAML
- **THEN** пакет показан со статусом «сломан» и причиной, называющей `package.yml`, а его состав помечен как не участвующий в поиске

#### Scenario: Затенённый пакет home
- **WHEN** пакет `hello` есть и в слое проекта, и в слое home
- **THEN** в секции «Home» `hello` показан со статусом «затенён пакетом проекта», а в секции «Project» — действующим

#### Scenario: Пустой слой
- **WHEN** каталога пакетов слоя нет или он пуст
- **THEN** секция слоя говорит, что пакетов нет, и называет путь каталога слоя

#### Scenario: Совпадение с CLI
- **WHEN** `GET /api/packages` и `stepcast package list --json` вызваны для одних и тех же корней
- **THEN** элементы `packages` ответа и вывода команды совпадают, включая `contents`

#### Scenario: Пункт меню
- **WHEN** пользователь открывает витрину со встроенной таблицей маршрутов
- **THEN** в группе `extend` есть пункт «Packages», ведущий на `/packages`

### Requirement: Экран «Packages» называет отказы файлов и конфликты `id` пакетов
Ответ `GET /api/packages` SHALL нести список `problems`, а экран «Packages» — показывать каждую запись у пакета, к которому она относится: отказ файла ресурса пакета из действующего состава демона (виджет, дашборд, `routes.yml`, каталожный плагин) с видом, именем, файлом и причиной словами движка, и конфликт — ресурс одного вида и имени у двух действующих пакетов одного слоя — с видом, именем и обоими пакетами. Конфликт MUST вычисляться для шагов и скриптов тоже и MUST NOT показываться дважды.

#### Scenario: Отказ дашборда пакета
- **WHEN** `dashboards/ops.yml` исправного пакета `hello` не проходит схему
- **THEN** в `problems` есть запись слоя проекта с пакетом `hello`, видом `dashboards`, `id` `ops`, файлом и причиной из `failures` состава дашбордов, а экран показывает её в карточке `hello`

#### Scenario: Конфликт виджета двух пакетов
- **WHEN** два действующих пакета слоя проекта приносят виджет `clock`
- **THEN** в `problems` ровно одна запись вида `widgets` с `id` `clock` и обоими пакетами, и экран показывает её в карточке каждого из двух пакетов

#### Scenario: Конфликт шага
- **WHEN** два действующих пакета слоя home приносят шаг `lint`
- **THEN** в `problems` есть запись вида `steps` с `id` `lint`, обоими пакетами и текстом конфликта движка

#### Scenario: Одинаковые имена в разных слоях
- **WHEN** пакет проекта и пакет home с разными именами приносят шаг `lint`
- **THEN** конфликта в `problems` нет

#### Scenario: Сломанный пакет конфликта не даёт
- **WHEN** один из двух пакетов слоя с виджетом `clock` сломан
- **THEN** конфликта по `clock` в `problems` нет, а сломанный пакет показан со своей причиной

#### Scenario: Ссылка с «Маршруты»
- **WHEN** экран «Маршруты» показывает предупреждение об отказе маршрутов пакета
- **THEN** предупреждение ведёт на `/packages`
