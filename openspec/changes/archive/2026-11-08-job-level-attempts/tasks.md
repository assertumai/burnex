## 3. Исполнение

- [x] 3.1 `runJob`: внешний цикл попыток вокруг цикла итераций `until`. Подготовка дерева, `resolveLate`, `syncLiveFiles`/`writebackLiveFiles` остаются вне цикла; `jobStartedAt` — от первой попытки
- [x] 3.2 Признак `terminal` у `JobOutcome`; белый список повторяемых причин (`expect_failed`, `timeout`, `spawn_failed`, `until_not_met`); `terminal` для противоречия плану возобновления и для необъявленного ключа данных
- [x] 3.3 Якорь начала работы сохраняется с первой попытки. Перед попыткой N > 1 — `restorePaths(start, changedPaths(start, last))`; при неудаче — `bookkeeping.failed` и исход последней попытки без нового захода
- [x] 3.4 Сброс `data.json` работы перед новой попыткой
- [x] 3.5 `sessionKey` получает номер попытки работы при `max > 1`; у работы без ключа он прежний
- [x] 3.6 Проверка бюджетов работы и прогона перед попыткой N > 1 (`budget_exceeded` с причиной о прекращении попыток); `sealStep` для шагов работы перед новой попыткой, номер попытки работы — в сводке расхода
- [x] 3.7 `exec/env.ts`: `STEPCAST_JOB_ATTEMPT` и `STEPCAST_JOB_ATTEMPT_MAX` у каждого шага и его проверок `expect`
- [x] 3.8 Промежуточные исходы не пишутся в `context.records`: статус работы остаётся `running` до финального исхода
- [x] 3.9 Тесты раннера: успех со второй попытки и откат дерева перед ней; исчерпание попыток; каждая неповторяемая причина и пропуск; `until_not_met` повторяется; новая сессия во второй попытке; сброс данных; неудача отката; бюджет; `on: failure` и `fail_fast` видят финальный исход; переменные окружения
