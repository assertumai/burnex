## ADDED Requirements

### Requirement: Участник цикла по группе работ показывает проходы на графе прогона и вывод по каждому проходу

Снимок прогона SHALL нести у каждой работы, входящей в цикл по группе работ (`loops`), сведения о цикле из записи `status.json`: идентификатор цикла, число начатых проходов, предел проходов, статус, вердикт законченного цикла, текущий проход — только пока цикл идёт, — и перечень проходов, чьи каталоги шагов этой работы есть на диске. Работа вне цикла MUST NOT нести этих сведений. Узел такой работы на графе прогона MUST показывать число проходов и текущий проход идущего цикла, а у законченного — число проходов и вердикт; высота узлов и раскладка графа MUST NOT зависеть от этих сведений. Маршрут вывода шага SHALL принимать необязательный номер прохода и читать каталог шага этого прохода, называя в ответе прочитанный проход; без номера MUST читаться последний проход, как прежде; номер, не являющийся положительным целым, MUST отклоняться ошибкой клиента; проход без каталога шага MUST давать пустой ответ, а не вывод другого прохода. Раскрытая работа-участник MUST позволять выбрать любой проход из перечня, по умолчанию последний, и показывать вывод каждого своего шага в выбранном проходе. Переключение попыток шага MUST работать как прежде — внутри выбранного прохода. Вывод не последнего прохода MUST считаться законченным и MUST NOT опрашиваться повторно.

#### Scenario: Идущий цикл на графе

- **WHEN** цикл `review` с `max_iterations: 5` идёт вторым проходом, и работа `fix` — его участник
- **THEN** узел `fix` на графе прогона показывает второй проход из пяти

#### Scenario: Законченный цикл на графе

- **WHEN** цикл закончился вердиктом `exhausted` после пяти проходов
- **THEN** узел каждого участника показывает пять проходов и вердикт `exhausted`, без текущего прохода

#### Scenario: Работа вне цикла

- **WHEN** работа не входит ни в один цикл по группе работ
- **THEN** снимок не несёт у неё сведений о цикле, и её узел выглядит как прежде

#### Scenario: Вывод шага прошлого прохода

- **WHEN** пользователь раскрывает работу-участник законченного цикла из трёх проходов и выбирает проход 1
- **THEN** вывод каждого шага работы читается из каталога `pass-1`, и ответ маршрута называет проход 1

#### Scenario: Без номера прохода читается последний

- **WHEN** маршрут вывода шага участника вызван без номера прохода
- **THEN** ответ содержит вывод последнего прохода, как до изменения

#### Scenario: Проход без каталога шага

- **WHEN** запрошен проход, в котором шаг работы не исполнялся и каталога шага нет
- **THEN** ответ пуст — без попыток и без вывода — и не подменяется выводом другого прохода

#### Scenario: Неверный номер прохода

- **WHEN** маршрут вывода шага получает `pass=0` или нечисловой `pass`
- **THEN** запрос отклоняется ошибкой клиента

#### Scenario: Попытки шага внутри прохода

- **WHEN** шаг во втором проходе исполнялся двумя попытками, и выбран проход 2
- **THEN** переключатель попыток шага предлагает обе попытки этого прохода
