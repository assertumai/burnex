## Why

Сменить значение переменной пайплайна на один запуск можно только правкой файла или входом `inputs`, под который переменная не заведена. Правка файла ради одного прогона оставляет след в дереве; вход требует, чтобы автор заранее объявил его и подставил в `env`.

## What Changes

- `stepcast run` принимает повторяемый флаг `--env KEY=VALUE`; `POST /api/run` — необязательное поле `env` (объект «ключ — строка»), которое демон передаёт дочернему `stepcast run` теми же ключами `--env`.
- Переопределить можно только ключ, объявленный в верхнеуровневом `env:` пайплайна. Необъявленный ключ и значение с переводом строки — отказ до запуска (ошибка конфигурации, для API — 400). Значение берётся буквально: `${...}` в нём не раскрывается, в отличие от значений самого `env:` документа.
- Решение: переопределения накладываются на `pipeline.env` при сборке окружения шага, а не правкой текста пайплайна, поэтому lock-хеш не меняется. Они пишутся в `run.json` ключом `env_overrides` (необязателен: у прогонов прежней версии его нет); `resume` читает их оттуда и применяет заново, собственного флага у него нет.
