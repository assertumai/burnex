## ADDED Requirements

### Requirement: Код пропуска проверяется до оценки результата

Если процесс командного шага завершился сам с кодом, равным действующему коду пропуска шага, попытка SHALL получать статус `skipped` без вычисления какой-либо проверки результата: предикатов `expect`, разбора `stdout` по `output_schema` шага `run`, чтения файла выхода шага `script` и судей.

Запись такой попытки MUST нести код возврата и причину, называющую код пропуска. Событие `expect.failed` для неё MUST NOT записываться.

Таймаут, отмена и несостоявшийся запуск процесса MUST NOT давать пропуск ни при каком коде: пропуск объявляет только процесс, сам дошедший до кода возврата.

#### Scenario: Пропуск без проверок

- **WHEN** шаг `run` с действующим кодом пропуска 78, предикатом `judge` в `expect` и `output_schema` выходит кодом 78 с пустым `stdout`
- **THEN** попытка получает `skipped`, судья не вызывается, а промаха `output_schema` в результатах нет

#### Scenario: Шаг script без файла выхода

- **WHEN** шаг `script` с объявленной `output_schema` выходит кодом пропуска, не записав файла выхода
- **THEN** попытка получает `skipped`, а не отказ по контракту файла выхода

#### Scenario: Другой ненулевой код

- **WHEN** шаг с действующим кодом пропуска 78 выходит кодом 1
- **THEN** попытка оценивается как прежде и не проходит проверку `exit_code`

#### Scenario: Шаг без кода пропуска

- **WHEN** ни один уровень не объявил код пропуска, а шаг выходит кодом 78
- **THEN** попытка оценивается как прежде и не проходит проверку `exit_code`

### Requirement: Пропуск — последняя попытка шага

Попытка, получившая `skipped`, SHALL быть последней попыткой шага: оставшиеся попытки `attempts.max` MUST NOT исполняться, а шаг MUST получать статус `skipped`.

#### Scenario: Пропуск на первой попытке

- **WHEN** шаг объявляет `attempts.max: 3`, а первая попытка вышла кодом пропуска
- **THEN** вторая и третья попытки не исполняются, а шаг получает `skipped` с одной записанной попыткой

#### Scenario: Пропуск после неудачной попытки

- **WHEN** первая попытка не прошла проверку, а вторая вышла кодом пропуска
- **THEN** шаг получает `skipped`, а в журнале записаны обе попытки

### Requirement: Код пропуска передаётся шагу через окружение

Командный шаг с действующим кодом пропуска SHALL получать его в переменной окружения `STEPCAST_SKIP_EXIT_CODE`, и её же MUST получать окружение предикатов этого шага; шаг без кода пропуска MUST NOT получать эту переменную.

#### Scenario: Скрипт выходит кодом из окружения

- **WHEN** пайплайн объявляет `skip_exit_code: 78`, а шаг исполняет `exit "$STEPCAST_SKIP_EXIT_CODE"`
- **THEN** шаг получает `skipped`

#### Scenario: Код не объявлен

- **WHEN** ни один уровень не объявил код пропуска
- **THEN** окружение шага не содержит `STEPCAST_SKIP_EXIT_CODE`
