## Why

GitHub Copilot CLI (`copilot`) — агентский CLI, который командам с подпиской
GitHub достаётся без отдельного договора с поставщиком модели. В burnex
адаптер к нему написан, но на живом CLI ни разу не запускался
(`docs/burnex-after-stepcast.md`, «`backend-copilot-live: postponed`»), так что
перенос его как есть дал бы ещё один бэкенд, работоспособность которого никто
не видел. Поэтому признаком выполненности здесь служит живой прогон шага, а не
только тесты с подменённым CLI, как у Cursor.

Copilot — ещё и третья проверка контракта бэкенда-плагина, и проверка самая
жёсткая. У Codex и Cursor был потоковый JSON. У Copilot в неинтерактивном
режиме (`-p`) есть только простой текст: ни записей, ни идентификатора
сессии, ни расхода. На этом контракт ломается в одном месте:

- `parseLine` не держит состояния между строками (экземпляр адаптера один на
  прогон и обслуживает одновременные шаги, `backend/types.ts`), а движок берёт
  текст шага из **последнего** события `result`
  (`run/exec/agentStep.ts`). Многострочный ответ, разобранный построчно,
  превратился бы в последнюю строку ответа. Этот текст читают судья
  (`judgePass.ts`) и `step.json`, так что потеря была бы тихой и опасной.
- Требование «Разбор потокового вывода» спеки `agent-backend` велит адаптеру
  запрашивать *структурированный* поток. Бэкенд без такого потока под него не
  подпадает вовсе.

## What Changes

- **Плагин `stepcast/backends/copilot`, бэкенд `copilot`.** Модуль
  `src/parts/backends/copilot/` (`index.ts`, `adapter.ts`) по образцу Cursor:
  подпуть `./backends/copilot` в `exports` у `package.json`, подключается
  ключом `plugins`, `builtinPlugin()` о нём не знает. Модуль импортирует только
  публичные подпути `stepcast/plugin` и `stepcast/pipeline` и встроенные модули
  Node. Граница плагинов пакета в `eslint.config.js` и перечень в
  `test/plugin-surface.test.ts` распространяются на него.
- **Запуск.** `copilot --allow-all --no-color -s` и промпт, модель передаётся
  через `--model`, рабочий каталог задаёт движок процессом. Промпт уходит через
  stdin, если установленная версия это поддерживает, иначе одним аргументом
  `--prompt=<промпт>` (слитная форма, чтобы промпт с `-` в начале не
  разбирался как флаг). Во втором случае `launch()` отказывает
  `StepcastError`, если промпт длиннее предела одного аргумента (128 KiB), а не
  оставляет падение `E2BIG` без объяснения. Какой путь выбрать, решает задача
  1.1 по `copilot --help` живой установки. `--allow-all` нужен потому, что без
  подтверждений неинтерактивный запуск ни одной правки не сделает. Граница
  доступа — рабочее дерево шага.
- **Правка ядра: событие `text`.** В `BackendEvent` добавляется вид
  `{ kind: 'text', text }` — кусок текстового ответа. Движок
  (`agentStep.ts`) склеивает такие куски переводом строки в порядке
  поступления. Текст из события `result` по-прежнему главнее: если он пришёл,
  куски отбрасываются. Адаптер Copilot отдаёт каждую строку stdout событием
  `text`, пустые строки тоже (иначе потеряются абзацы). У Claude, Codex и
  Cursor ничего не меняется: событий `text` они не отдают.
- **Возможности объявлены честно:** `sessions: false`,
  `sessionIdSource: 'backend'` (идентификатора поток не несёт, и движок не
  заводит выдуманный), `structuredOutput: false`, `strictPermissions: false`,
  `mcp: false`, `effort: false`, `reportsCost: false`. Вклада `models` нет:
  перечня моделей CLI не даёт, и страница «Агенты» говорит это своей готовой
  фразой. Всё, что из этого следует, движок уже умеет: `session: shared`
  деградирует до `per_step` с предупреждением, `output_schema`, `mcp`,
  `enforce: strict` и судья на `copilot` отклоняются до старта, effort
  документа отклоняет прогон, а effort настроек отбрасывается с
  `backend.degraded` — «как у Cursor».
- **Доступ.** Словаря режимов у адаптера нет: `--allow-all` разрешает всё.
  Поэтому любое `permissions.mode` и непустые `allow`/`deny` дают
  `StepcastError` из `launch()` с именем бэкенда и объявлением. Перевод в
  `--allow-tool`/`--deny-tool` в изменение не входит.
- **Расход и отказы.** Событий `usage` нет, поля расхода остаются
  несообщёнными, а не нулями. Отказ лимита или аутентификации по тексту stdout
  не классифицируется: это ответ агента, и совпадение слов «rate limit» в нём
  не означает отказа. Неудачный выход процесса проваливает попытку обычным
  путём.
- **Умолчания вклада:** `command: copilot`, `sessions: false`,
  `structured_output: false`, `strict_permissions: false`, `mcp: false`,
  `concurrency: 2`. `default_model` не задаётся, действует умолчание CLI.
- **Тесты адаптера:** `test/copilot-adapter.test.ts` проверяет сборку
  запуска, отказы доступа, разбор строк и исполнение шага через исполняемую
  подмену `copilot`, печатающую многострочный ответ (весь текст дошёл до
  `step.json`). Тест ядра на событие `text` — в `test/backend.test.ts`.
- **Живой прогон.** Один шаг пайплайна `examples/copilot/` исполняется на
  установленном и залогиненном `copilot`. Версия CLI, команда, итог шага и
  выдержка из `step.json` записываются в раздел «Живой прогон» в `design.md`
  этого изменения.
- **Документация:** в `docs/plugins.md` появляется раздел «Четвёртый бэкенд:
  Copilot» (что понадобилось, чего хватило, чего не хватило) и описание
  события `text` в контракте `parseLine`. В `docs/config.md` — подключение,
  умолчания, отказ `permissions`, отсутствие сессий, расхода и списка моделей,
  а также переменные токена GitHub под `env_deny`.

## Capabilities

### New Capabilities
- `copilot-backend`: адаптер GitHub Copilot CLI плагином пакета: сборка
  запуска, текстовый разбор вывода, честно выключенные возможности, отказ
  `permissions`, умолчания вклада, тесты с подменённым CLI и живой прогон.

### Modified Capabilities
- `agent-backend`: требование «Разбор потокового вывода» допускает бэкенд,
  который структурированного потока не даёт, и вводит событие текстового
  куска, которое движок склеивает в текст шага.

## Impact

- Новые файлы: `src/parts/backends/copilot/{index,adapter}.ts`,
  `test/copilot-adapter.test.ts`, `test/fixtures/copilot/`,
  `examples/copilot/`.
- `package.json`: подпуть `./backends/copilot`. `eslint.config.js` (границы
  `files` и тексты сообщений), `test/eslint-config.test.ts`,
  `test/plugin-surface.test.ts`, `test/plugin-load.test.ts`.
- Ядро: `src/parts/pipeline/backend/types.ts` (вид события `text`),
  `src/parts/pipeline/run/exec/agentStep.ts` (склейка кусков). `judgePass.ts`
  не меняется: судья на бэкенде без структурированного вывода отклонён
  заранее.
- Документация: `docs/plugins.md`, `docs/config.md`.
- Вне изменения: перевод `permissions.allow`/`deny` в
  `--allow-tool`/`--deny-tool`, продолжение сессий через `--resume`, разбор
  статистики расхода из вывода без `-s`, карточка `copilot` в витрине
  настроек. Если окажется, что у живого CLI есть потоковый JSON, переход на
  него тоже вынесен отдельным пунктом.
