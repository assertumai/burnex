## MODIFIED Requirements

### Requirement: Разбор потокового вывода

Адаптер SHALL запрашивать у бэкенда потоковый структурированный вывод, если бэкенд его даёт, и разбирать вывод по мере поступления. Из потока MUST извлекаться текстовый результат, структурированный вывод, расход и перечень вызовов инструментов — то из них, что поток несёт. Бэкенд без структурированного потока MAY отдавать текст ответа событиями текстового куска (`text`), по одному на строку; движок MUST склеивать такие куски переводом строки в порядке поступления в текст шага, отсекая пустые куски по краям, а текст события `result`, если оно его несёт, MUST оставаться главнее склеенных кусков. Неразбираемая строка потока MUST записываться в журнал и MUST NOT прерывать шаг.

#### Scenario: Инкрементальный расход

- **WHEN** бэкенд сообщает расход по ходу работы
- **THEN** учёт обновляется до завершения процесса, а не только по его окончании

#### Scenario: Битая строка потока

- **WHEN** строка потока не разбирается как ожидаемая запись
- **THEN** она сохраняется в журнал, а обработка потока продолжается

#### Scenario: Многострочный текстовый ответ

- **WHEN** адаптер отдаёт на три строки вывода события `text` с текстами `Итог:`, пустым и `готово`, а события `result` с текстом нет
- **THEN** текст шага равен `Итог:\n\nготово`

#### Scenario: Пустые куски по краям

- **WHEN** адаптер отдаёт события `text` с текстами пустым, `Итог:`, пустым, `готово` и пустым, а события `result` с текстом нет
- **THEN** текст шага равен `Итог:\n\nготово`

#### Scenario: Итоговый текст главнее кусков

- **WHEN** адаптер отдал события `text`, а затем событие `result` с текстом
- **THEN** текст шага равен тексту события `result`
