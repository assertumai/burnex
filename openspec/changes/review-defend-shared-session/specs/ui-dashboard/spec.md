## MODIFIED Requirements

### Requirement: Лента режима defend показывает раунды защиты

В режиме `defend` лента SHALL начинаться системной строкой о защитнике:

- сессия имплементатора с названием шага, агентом и моделью — для `resume`;
- форк этой сессии с причиной `reused` или `shared` — для `fork`;
- свежий агент с причиной — для `fresh`.

Карточка находки MUST нести:

- id находки;
- бейдж статуса: `open`, `accepted`, `withdrawn` или `contested`;
- серьёзность с отметкой пересмотра.

После сообщений ревьюеров с находками реплики MUST идти по раундам: реплика защитника раунда, затем ответы ревьюеров этого раунда. В реплике защитника ответы MUST быть сгруппированы по ревьюерам: у каждой группы подпись ревьюера и его цвет. Защитник MUST стоять на стороне, противоположной ревьюерам.

Ответ MUST показываться по находкам:

- с текстовой меткой позиции:
  - `accepts`, `disputes`, `clarifies` у защитника;
  - `maintains`, `withdraws`, `revises → <серьёзность>` у ревьюера;
- с доводом;
- с доказательством, если оно есть.

Невалидная или упавшая реплика MUST быть помечена.

Журнал прежнего формата с ветками защитника MUST показываться прежней лентой: реплики ветки под находками своего ревьюера.

#### Scenario: Раунд со спором

- **WHEN** пользователь открывает шаг, где защитник в раунде 1 оспорил `security.1` и принял `tests.1`, а ревьюер `security` отстоял свою находку
- **THEN** он видит одну реплику защитника раунда 1 с группами `security` (метка `disputes` и доказательство) и `tests` (метка `accepts`), затем ответ `security` с меткой `maintains`

#### Scenario: Защитник — сессия имплементатора

- **WHEN** защитник — сессия шага `build.implement` на Claude, возобновлённая на месте
- **THEN** первая строка ленты называет сессию имплементатора, `build.implement`, `claude` и модель

### Requirement: Боковая панель ленты показывает находки, раунды и расход

Рядом с лентой SHALL показываться:

- список находок со статусом и итоговой серьёзностью;
- число прошедших раундов защиты из `rounds` и число ходов каждого ревьюера; для журнала прежнего формата — раунды по веткам;
- расход и время по каждому участнику, включая `defender`, и по шагу.

На узкой ширине панель MUST располагаться под лентой.

#### Scenario: Итог защиты

- **WHEN** защита закончилась с тремя `accepted`, одной `withdrawn` и одной `contested`
- **THEN** панель показывает пять находок с этими статусами

### Requirement: Редактор стратегии предлагает режим defend

Редактор стратегии SHALL предлагать переключатель режима «Independent / Defend».

В режиме `defend` редактор MUST показывать:

- поле `rounds` (1–5);
- блок выбора агента защитника с пояснением: когда у шага есть имплементатор с сессией, защищает сама эта сессия, а блок выбирает агента, когда её нет;
- схему хода «Reviewers in parallel → Defend with implementer ≤ R rounds → Aggregator decides contested».

Стратегия с прежним `mode: discussion` MUST показываться с ошибкой разбора у ключа `mode`.

#### Scenario: Переключение на defend

- **WHEN** пользователь выбирает режим Defend
- **THEN** появляются поле `rounds` со значением 2 и блок защитника, а сохранение пишет `mode: defend` с сохранением комментариев файла
