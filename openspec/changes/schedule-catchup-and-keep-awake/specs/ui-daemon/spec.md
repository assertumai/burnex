## ADDED Requirements

### Requirement: Демон несёт сервис триггеров

При `ui.triggers.enabled: true` демон SHALL раз в минуту отрабатывать расписания — `triggers.schedule` пайплайнов проекта, в котором он поднят, и записи `ui.triggers.schedules` домашнего конфига — и запускать прогон тем же путём, что `POST /api/run`, отсоединённым процессом. Умолчание `enabled` MUST быть `false`: без явного включения демон MUST NOT запускать прогоны по расписанию. Остановка демона MUST NOT прерывать прогоны, запущенные сервисом. Собственное состояние сервиса — последние рассмотренные моменты и решения — MUST лежать рядом с pid-файлом демона, вне каталогов прогонов, и MUST переживать перезапуск демона.

#### Scenario: Сервис выключен по умолчанию

- **WHEN** пайплайн проекта объявляет `triggers.schedule`, демон поднят, а `ui.triggers.enabled` не задан
- **THEN** наступивший момент прогона не запускает, а экран расписаний показывает, что сервис выключен

#### Scenario: Сервис включён

- **WHEN** `ui.triggers.enabled: true` и наступил момент расписания
- **THEN** демон запускает прогон отсоединённым процессом, а журнал прогона пишет сам прогон

#### Scenario: Остановка демона не трогает прогон

- **WHEN** `stepcast down` вызвана во время прогона, запущенного по расписанию
- **THEN** демон завершается, а прогон продолжает работать

#### Scenario: Демон проснулся после сна

- **WHEN** таймер оборота сработал с опозданием из-за сна машины
- **THEN** оборот рассматривает моменты по настенному времени, а не по числу пропущенных тиков

#### Scenario: Демон поднят вне проекта

- **WHEN** демон поднят в каталоге без проекта, а `ui.triggers.schedules` содержит записи
- **THEN** срабатывают записи домашнего конфига, а расписаний из файлов пайплайнов нет
