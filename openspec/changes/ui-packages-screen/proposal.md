## Why

Пакеты (`packages-directory-layer`) приносят пайплайны, шаги, скрипты,
плагины, виджеты, дашборды и маршруты, и демон уже отдаёт их сводку —
`GET /api/packages` (строка `ui-packages` без экрана). Но витрина её не
показывает: о пакетах на ней напоминает только предупреждение
`packageFailures` на «Маршруты», и то лишь об отказах маршрутов. Какие именно
ресурсы пришли из пакета, почему пакет сломан или затенён и какой его файл или
`id` отказал в составе — видно только в `stepcast package list` и по журналам
(`docs/ui-proposals.md`, п. 2: «каталог пакетов, состав, ошибки слоя»).

К тому же нынешняя сводка отвечает лишь «какие виды ресурсов есть»
(`provides`), а не «какие ресурсы»: имён шагов, виджетов, дашбордов в ней нет,
и экран из неё один не собрать.

## What Changes

- **Состав пакета в общей модели.** `PackageSummary`
  (`src/parts/packages/summary.ts`) получает поле `contents`: имена ресурсов по
  видам — пайплайны, шаги, скрипты, плагины, виджеты, дашборды, маршруты
  (`id` из `routes.yml`). Модель общая с `stepcast package list --json`, поле
  аддитивно; текстовый вывод `package list` не меняется. `provides` остаётся.
- **Отказы, привязанные к пакетам.** Ответ `GET /api/packages` получает рядом
  с `packages` список `problems`: отказы файлов пакетных ресурсов из действующих
  составов демона (виджет с `error`, `failures` дашбордов, отказ `routes.yml`
  пакета, отказавшая строка каталожного плагина пакета) и конфликты `id` внутри
  слоя — ресурс одного вида и имени у двух исправных пакетов одного слоя. У
  каждой записи — слой, пакет(ы), вид, имя/`id`, файл, если он есть, и причина
  словами движка. `packages` по-прежнему совпадает со `stepcast package list
  --json`.
- **Экран «Packages»** — `ui/src/pages/Packages.tsx` и
  `ui/src/screens/packages.tsx`: две секции, «Project» и «Home»; по пакету —
  имя, версия, описание, путь каталога, статус (действует / сломан с причиной /
  затенён пакетом проекта), состав по видам, незакрытые `needs` и отказы этого
  пакета. Конфликт показан у обоих пакетов.
- **Строка и маршрут.** Строка `ui-packages` становится экранной
  `screen-packages` (объявление экрана и тот же `GET /api/packages`), маршрут
  `screen-packages` на `/packages`, `nav: { group: extend, order: 3 }`.
- **«Маршруты» ссылаются на экран:** предупреждение `packageFailures` ведёт на
  `/packages`.
- **Тесты**: модель `contents` и конфликтов на временных пакетах обоих слоёв;
  ответ API со сломанным, затенённым пакетом, отказом дашборда и конфликтом
  виджета; разметка экрана по фикстуре; ожидания таблицы маршрутов и экранов.
- **Документация**: раздел «Витрина» в `docs/packages.md` ссылается на экран
  «Packages» и описывает `problems`.

## Impact

- Код: `src/parts/packages/summary.ts` (`contents`, функция конфликтов),
  `src/parts/packages/commands/` (только `--json` получает поле),
  `src/parts/ui/packages/row.ts` → `src/parts/ui/screens/packages/{declaration,server}.ts`,
  `src/parts/ui/packages.ts` (сведение `problems` из составов наблюдателя и ядра
  демона), `src/parts/ui/rows.ts`, `src/builtin/routes.yml`,
  `ui/src/pages/Packages.tsx` + `packages.css`, `ui/src/screens/packages.tsx`,
  `ui/src/screens/index.ts`, `ui/src/pages/RoutesEditor.tsx` (ссылка).
- API: `GET /api/packages` — аддитивные поля `contents` у пакета и `problems`
  в ответе. Только чтение; витрина в каталог пакета не пишет.
- Идентификатор строки поставки `ui-packages` уходит: патч, который его
  называет, указывает на `screen-packages`.
- Зависимостей не добавляется.
