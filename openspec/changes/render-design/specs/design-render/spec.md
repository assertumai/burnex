## ADDED Requirements

### Requirement: Команда burnex render design

CLI SHALL предоставлять команду `burnex render design <файл> --format html|openspec [--out <путь>]`. `<файл>` — путь к JSON-документу формы `burnex:design-doc`. Без `--out` результат MUST печататься в stdout; с `--out` MUST записываться в файл целиком, а команда — печатать путь записанного файла. Команда MUST работать без конфигурации проекта и вне прогона. Неизвестный вид рендера, неизвестный `--format`, отсутствующий `--format` и отсутствующий файл MUST давать отказ с кодом ошибки конфигурации и перечнем допустимых значений.

#### Scenario: HTML в файл

- **WHEN** выполняется `burnex render design out.json --format html --out design.html` для корректного документа
- **THEN** команда завершается успешно, `design.html` содержит документ, а stdout — путь `design.html`

#### Scenario: OpenSpec в stdout

- **WHEN** выполняется `burnex render design out.json --format openspec` без `--out`
- **THEN** Markdown документа печатается в stdout

#### Scenario: Неизвестный формат

- **WHEN** `--format pdf`
- **THEN** команда отказывает кодом ошибки конфигурации и называет `html` и `openspec`

### Requirement: Вход проверяется схемой burnex:design-doc

Рендер SHALL снимать с входа поля движка `agreed`, `unresolved`, `changed_by_aggregator`, проверять остаток схемой `burnex:design-doc`, а поля движка — по типам (`agreed` boolean, остальные — массивы строк). Поля движка MUST быть необязательными. Вход, не разобранный как JSON, и вход, не прошедший проверку, MUST давать отказ с путём файла и путём первого ключа с ошибкой.

#### Scenario: Документ без полей движка

- **WHEN** вход — документ `burnex:design-doc` без `agreed`
- **THEN** рендер проходит и не выводит отметок согласия

#### Scenario: Чужая схема

- **WHEN** вход — объект без `decisions`
- **THEN** рендер отказывает и называет путь `decisions`

### Requirement: Офлайн-HTML

HTML-рендер SHALL давать один самодостаточный файл без сетевых ссылок: стили встроены, скрипт Mermaid встроен из бандла, поставляемого пакетом burnex. Весь текст документа MUST экранироваться. Исходники диаграмм MUST выводиться в блоках, которые Mermaid отрисовывает на месте с `securityLevel: 'strict'`; блок, который отрисовать не удалось, MUST оставаться исходником с текстом ошибки. Документ без диаграмм MUST не содержать скрипта. Решения MUST иметь якоря `#<id>`, подписи диаграмм — ссылки на них. При `agreed: false` в начале документа MUST стоять пометка о несогласованном итоге со списком `unresolved`; решения из `changed_by_aggregator` MUST помечаться. Если бандла нет в сборке, рендер документа с диаграммами MUST отказывать с подсказкой пересобрать пакет.

#### Scenario: Нет сетевых ссылок

- **WHEN** рендерится документ с двумя диаграммами
- **THEN** в HTML нет `http://` и `https://` в атрибутах `src` и `href`, есть встроенный скрипт и два блока диаграмм

#### Scenario: Экранирование

- **WHEN** `summary` содержит `<script>alert(1)</script>`
- **THEN** в HTML этот текст выведен экранированным, а исполняемых тегов из документа нет

#### Scenario: Без диаграмм — без скрипта

- **WHEN** `diagrams` пуст
- **THEN** HTML не содержит тега `<script>`

### Requirement: OpenSpec design.md

OpenSpec-рендер SHALL давать Markdown с заголовком `# <title>` и разделами в порядке шаблона OpenSpec: `## Context` (summary), `## Decisions` (каждое решение — `### <id>. <question>`, выбор, обоснование, отклонённые варианты с автором и причиной), `## Diagrams` (каждая диаграмма — заголовок, точки решения и блок ` ```mermaid `), `## Risks / Trade-offs`, `## Open Questions`. Пустые `Diagrams`, `Risks / Trade-offs` и `Open Questions` MUST опускаться. Исходник диаграммы с тройным бэктиком MUST обрамляться более длинной оградой. При `agreed: false` и непустом `changed_by_aggregator` перед `Context` MUST стоять пометки, как у HTML.

#### Scenario: Разделы по шаблону

- **WHEN** документ имеет решения, диаграмму и риски, но не вопросы
- **THEN** Markdown содержит `## Context`, `## Decisions`, `## Diagrams`, `## Risks / Trade-offs` и не содержит `## Open Questions`

#### Scenario: Ограда диаграммы

- **WHEN** исходник диаграммы содержит строку ` ``` `
- **THEN** блок обрамлён оградой из четырёх бэктиков

### Requirement: Рендеры детерминированы

Оба рендера SHALL быть детерминированными: одинаковый вход MUST давать побайтно одинаковый результат, без дат, путей и случайных идентификаторов.

#### Scenario: Два прогона рендера

- **WHEN** один документ рендерится дважды в HTML
- **THEN** результаты совпадают побайтно
