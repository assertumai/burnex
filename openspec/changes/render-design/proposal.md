## Why

Шаг `discuss` (`discuss-step`) выдаёт проектный документ по схеме
`burnex:design-doc`: решения, отклонённые варианты, диаграммы Mermaid,
риски, открытые вопросы и поля движка. Сейчас этот документ — только JSON в
`output.json`. Витрина показывает его сырым выводом шага, диаграммы не
рисуются, а ход обсуждения (предложения, черновик, возражения, защита) виден
только по файлам каталога шага.

Пользователь выбрал три формы артефактов (обсуждение 2026-11-13): диаграммы
Mermaid внутри документа, их отрисовку в витрине и детерминированный рендер
документа в HTML и в OpenSpec `design.md`. Этого нет.

## What Changes

- **Команда `burnex render design <файл> --format html|openspec [--out <путь>]`.**
  Вход — явный путь к JSON документа `burnex:design-doc`: `output.json`
  шага, `artifacts/<работа>.json` либо любой файл той же формы. Поля движка
  (`agreed`, `unresolved`, `changed_by_aggregator`) необязательны. Документ
  проверяется схемой `burnex:design-doc` до рендера. Без `--out` результат
  идёт в stdout.
- **HTML офлайн.** Один самодостаточный файл: стили встроены, Mermaid
  встроен из бандла, поставляемого пакетом (`dist/vendor/mermaid.min.js`),
  без CDN и сетевых запросов. Документ без диаграмм скрипта не несёт.
  Битая диаграмма показывается исходником с текстом ошибки.
- **OpenSpec `design.md`.** Markdown с разделами шаблона OpenSpec (`Context`,
  `Decisions`, `Risks / Trade-offs`, `Open Questions`), диаграммы — блоками
  ` ```mermaid `. Несогласованный итог помечен в начале документа.
- Оба рендера детерминированы: одинаковый вход даёт одинаковые байты.
- **Витрина: лента шага `discuss`.** В деталях прогона шаг `discuss`
  показывается своей панелью, а не сырым выводом:
  - участники с ролями, бэкендом, моделью, расходом и ссылками на поток
    вызова;
  - фазы и их состояние, пока шаг идёт;
  - предложения участников, черновик автора;
  - возражения по точкам решения с весом и исходом, реплики раундов защиты
    лентой;
  - итоговый документ с отрисованными диаграммами Mermaid, отметками
    `agreed`, `unresolved`, `changed_by_aggregator`;
  - кнопки скачать HTML и OpenSpec `design.md` (тот же рендер, что у
    команды).
- `GET /api/discuss-feed`, `GET /api/design-render` и `GET /api/vendor/mermaid.js` демона.
- Mermaid в витрине загружается лениво, только когда на экране есть
  диаграмма: демон отдаёт тот же бандл (`GET /api/vendor/mermaid.js`), что
  встраивает офлайн-HTML. Страница витрины не растёт.
- Общие помощники чтения журнала участников (`readCall`, `readNdjson`,
  `reusedSource` и др.) выносятся из `reviewFeed.ts` в общий модуль: ими
  пользуются обе ленты.

Вне этого изменения:
- редактор стратегий обсуждения в витрине — отдельное изменение;
- PlantUML и другие виды диаграмм;
- проверка синтаксиса Mermaid движком при исполнении шага;
- запись `design.md` прямо в `openspec/changes/<имя>/` по имени изменения:
  путь называет `--out`.

## Capabilities

### New Capabilities
- `design-render`: команда `burnex render design` и рендеры документа
  `burnex:design-doc` в офлайн-HTML и OpenSpec `design.md`.
- `discuss-feed`: лента шага `discuss` в деталях прогона — участники, фазы,
  возражения, раунды, итоговый документ с диаграммами и скачивание рендеров.

### Modified Capabilities
<!-- нет: шаг discuss и его журнал не меняются -->

## Impact

- Код: новый `src/parts/pipeline/render/` (рендеры), команда
  `src/parts/pipeline/commands/render.ts`, `src/parts/ui/discussFeed.ts`,
  общий `src/parts/ui/participantJournal.ts`, маршруты в
  `src/parts/ui/screens/run/server.ts`; витрина — `DiscussFeed.tsx`,
  `DesignDoc.tsx`, `Mermaid.tsx`, ветка в `RunDetail.tsx`.
- Зависимости: `mermaid@12.2.0` — devDependency. Бандл копируется сборкой в
  `dist/vendor/` и едет в релизе и пакете, рантайм-зависимостью движка он не
  становится. HTML с диаграммами весит около 5,5 МБ из-за встроенного
  бандла.
- Справка CLI (`burnex render`), эталон справки, документация
  `docs/pipeline-format.md` (раздел `discuss`), пример `examples/discuss`.
- Журнал и формат шага не меняются, `JOURNAL_FORMAT` прежний.
