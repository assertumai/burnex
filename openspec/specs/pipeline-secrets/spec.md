## Requirements
### Requirement: Встроенный провайдер секретов keychain

Система SHALL регистрировать встроенный провайдер секретов `keychain`, значение которого — вывод `security find-generic-password -a <account> -s <service> -w` без завершающего перевода строки.
Параметры `service` и `account` MUST быть обязательными непустыми строками,
прочие параметры MUST отклоняться схемой провайдера. Команда MUST запускаться
без оболочки и MUST прерываться по истечении 5 секунд или по отмене прогона.
Не на macOS провайдер MUST отказывать, не запуская команды. Отсутствующая
запись, таймаут и ненулевой код возврата MUST давать отказ разрешения с
`service` и `account`, а сообщение отказа MUST NOT содержать вывода команды.
Провайдер MUST регистрироваться тем же путём, что `env-file`.

#### Scenario: Значение из связки ключей

- **WHEN** секрет объявлен с `provider: keychain`, `service: github.com`, `account: alice`, а команда печатает значение и перевод строки
- **THEN** шаг, назвавший секрет, получает значение без завершающего перевода строки

#### Scenario: Не macOS

- **WHEN** прогон с названным шагом секретом `provider: keychain` запущен не на macOS
- **THEN** запуск отклонён до создания каталога прогона с объяснением, что провайдер доступен только на macOS
- **AND** команда `security` не запускалась

#### Scenario: Записи нет

- **WHEN** команда завершилась кодом 44
- **THEN** запуск отклонён с именем секрета, `service` и `account`, каталог прогона не создан

#### Scenario: Команда не отвечает

- **WHEN** команда не завершилась за 5 секунд
- **THEN** процесс команды остановлен, а запуск отклонён с указанием таймаута и без каталога прогона

#### Scenario: Без account

- **WHEN** секрет с `provider: keychain` не указывает `account`
- **THEN** `stepcast lint` и запуск отклоняют объявление с указанием параметра

#### Scenario: Линт не проверяет платформу

- **WHEN** документ с секретом `provider: keychain` проверяется `stepcast lint` не на macOS
- **THEN** линт не сообщает об ошибке платформы

### Requirement: Объявление секретов в документе пайплайна

Документ пайплайна SHALL принимать верхний ключ `secrets:` — словарь секретов по имени с обязательным `provider`, параметрами провайдера и необязательным `env`.
Имя секрета MUST соответствовать `^[a-z][a-z0-9_-]{0,63}$`. Умолчание `env` —
имя в верхнем регистре с заменой `-` на `_`; `env` с префиксом `STEPCAST_` MUST
отклоняться. Параметры провайдера MUST проверяться JSON-схемой его вклада.
Файлы работ и манифесты переиспользуемых шагов MUST NOT объявлять секреты.
Объявление MUST попадать в замок прогона без значения.

#### Scenario: Умолчание имени переменной

- **WHEN** пайплайн объявляет секрет `gh-token` без ключа `env`
- **THEN** значение секрета доходит до объявившего шага переменной `GH_TOKEN`

#### Scenario: Недопустимое имя

- **WHEN** пайплайн объявляет секрет с именем `GH_Token`
- **THEN** разбор документа отклоняет его с указанием имени и шаблона

#### Scenario: Префикс движка

- **WHEN** секрет объявляет `env: STEPCAST_TOKEN`
- **THEN** разбор документа отклоняет объявление

#### Scenario: Секрет в файле работы

- **WHEN** файл работы содержит ключ `secrets:` верхнего уровня
- **THEN** разбор отклоняет его с указанием, что секреты объявляются только пайплайном

#### Scenario: Замок без значения

- **WHEN** прогон с объявленным секретом стартовал
- **THEN** `pipeline.lock.yml` содержит имя, провайдер, параметры и `env` секрета и не содержит его значения

### Requirement: Точечная выдача секрета шагу

Шаг `run`, `script`, `uses` и шаг плагинного вида SHALL получать значения секретов, названных в его ключе `secrets: [имя, …]`, и только их.
Значение MUST доходить до процесса шага (а плагинному шагу — полем `env` входа
исполнителя) переменной `env` секрета. Ссылка на необъявленный секрет MUST
отклоняться разбором и `stepcast lint`. Имена секретов шага MUST входить в ключ
шага, значения — MUST NOT.

#### Scenario: Объявивший шаг получает значение

- **WHEN** командный шаг объявляет `secrets: [gh-token]`
- **THEN** его процесс получает переменную `GH_TOKEN` со значением секрета

#### Scenario: Соседний шаг не получает значение

- **WHEN** в той же работе другой командный шаг не называет `gh-token`
- **THEN** переменной `GH_TOKEN` в его окружении нет

#### Scenario: Ссылка на необъявленный секрет

- **WHEN** шаг называет `secrets: [missing]`, а пайплайн такого секрета не объявляет
- **THEN** `stepcast lint` и запуск отклоняют документ с именем секрета и адресом шага

#### Scenario: Ротация не меняет ключ шага

- **WHEN** значение секрета сменилось между прогоном и его возобновлением
- **THEN** ключ шага, назвавшего секрет, не изменился

### Requirement: Агент секрета не получает

Агентский шаг и судья `judge` SHALL NOT принимать ключ `secrets`, и значение никакого секрета MUST NOT доходить до процесса агентского бэкенда.
Переменная `env` объявленного секрета, пришедшая в окружение агентского шага из
окружения процесса или `env_files`, MUST вычёркиваться.

#### Scenario: Ключ на агентском шаге

- **WHEN** агентский шаг объявляет `secrets: [gh-token]`
- **THEN** `stepcast lint` и разбор документа отклоняют шаг с объяснением, что агенту секрет не передаётся

#### Scenario: Переменная секрета в окружении процесса

- **WHEN** окружение процесса stepcast содержит `GH_TOKEN`, а пайплайн объявляет секрет с этим `env`
- **THEN** процесс агентского шага запускается без переменной `GH_TOKEN`

### Requirement: Разрешение секретов до создания каталога прогона

Система SHALL разрешать значения всех секретов, на которые ссылается хотя бы один шаг, до создания каталога прогона и отказывать в запуске при любом сбое разрешения.
Отказ MUST следовать, если провайдер не зарегистрирован, параметры не проходят
схему, провайдер завершился ошибкой или вернул не строку, значение пусто, короче
8 символов или содержит перевод строки. При отказе каталог прогона MUST NOT
создаваться. Секрет, на который не ссылается ни один шаг, MUST NOT разрешаться.
Возобновление прогона MUST разрешать секреты заново тем же порядком.

#### Scenario: Короткое значение

- **WHEN** провайдер вернул для секрета значение из 6 символов
- **THEN** запуск отклонён с именем секрета и порогом в 8 символов
- **AND** каталог прогона не создан

#### Scenario: Неизвестный провайдер

- **WHEN** секрет объявляет `provider: vault`, а такой провайдер не зарегистрирован
- **THEN** запуск отклонён с именем провайдера, а `stepcast lint` отклоняет объявление ещё до запуска

#### Scenario: Неиспользуемый секрет

- **WHEN** секрет объявлен, но ни один шаг его не называет, а его файл отсутствует
- **THEN** прогон стартует, а `stepcast lint` предупреждает о неиспользуемом секрете

### Requirement: Маскирование значений в журнале прогона

Система SHALL заменять каждое вхождение значения разрешённого секрета на `***` в стандартных потоках шагов, в потоке агентского шага, в `prompt.txt` агентского шага и судьи и в `events.ndjson`.
Маскирование потоков MUST применяться к собранной строке, а не к отдельному
куску вывода. Значения MUST заменяться от более длинного к более короткому.

#### Scenario: Шаг печатает секрет

- **WHEN** командный шаг, получивший секрет, печатает его значение в стандартный вывод
- **THEN** `stdout.log` шага содержит `***` на месте значения и не содержит самого значения

#### Scenario: Значение на стыке кусков вывода

- **WHEN** значение секрета пришло от процесса двумя кусками без перевода строки между ними
- **THEN** записанная строка лога содержит `***` и не содержит ни значения, ни его частей по обе стороны стыка

#### Scenario: Секрет в промпте

- **WHEN** выход предыдущей работы, вставленный в промпт агентского шага, содержит значение секрета
- **THEN** `prompt.txt` шага содержит `***` на месте значения

### Requirement: Подстановка env не раскрывает секреты

Подстановка `${env.<имя>}` SHALL отказывать, если имя — `env` объявленного секрета либо значение переменной содержит значение разрешённого секрета.
Отказ MUST быть отказом работы с объяснением, называющим секрет, а для имени,
являющегося `env` объявленного секрета, `stepcast lint` MUST отклонять
подстановку до запуска.

#### Scenario: Подстановка переменной секрета

- **WHEN** промпт агентского шага содержит `${env.GH_TOKEN}`, а `GH_TOKEN` — `env` секрета `gh-token`
- **THEN** `stepcast lint` отклоняет подстановку с именем секрета
- **AND** при запуске без линта работа завершается отказом до первого шага, а значение нигде не записано

#### Scenario: Переменная со встроенным значением секрета

- **WHEN** `DATABASE_URL` в окружении содержит значение разрешённого секрета, а аргумент шага ссылается на `${env.DATABASE_URL}`
- **THEN** работа завершается отказом с объяснением, что значение переменной содержит секрет

### Requirement: Событие env.withheld

Система SHALL писать в журнал событие `env.withheld` с именем переменной, именем секрета и адресом шага, когда переменная секрета вычеркнута из окружения шага, который этот секрет не объявил.
Событие MUST писаться не более одного раза на пару «переменная, шаг» и MUST NOT
писаться, если переменной в собранном окружении шага не было.

#### Scenario: Вычеркнутая переменная

- **WHEN** `env_files` содержит `GH_TOKEN`, секрет `gh-token` объявлен, а шаг `build` его не называет
- **THEN** журнал событий содержит `env.withheld` с `name: GH_TOKEN`, `secret: gh-token` и адресом шага `build`

#### Scenario: Переменной не было

- **WHEN** ни окружение процесса, ни `env_files` не содержат `GH_TOKEN`
- **THEN** событий `env.withheld` для `GH_TOKEN` в журнале нет

### Requirement: Провайдеры секретов — вклад плагина

Контракт `stepcast/pipeline` SHALL принимать вклад провайдера секретов — имя, JSON-схему параметров и функцию `resolve`, возвращающую значение строкой.
Встроенный провайдер `env-file` MUST регистрироваться тем же путём, что и
плагинный, и MUST читать значение ключа `key` (умолчание — `env` секрета) из
файла `file`, относительный путь которого разрешается от корня проекта.
Отсутствующий файл или ключ MUST давать отказ разрешения, а не пустое значение.
Занятое имя провайдера MUST отклоняться при регистрации.

#### Scenario: Свой провайдер

- **WHEN** плагин вносит провайдер `vault`, а пайплайн объявляет секрет с `provider: vault`
- **THEN** значение секрета берётся из результата `resolve` этого вклада

#### Scenario: env-file без ключа

- **WHEN** секрет с `provider: env-file` указывает файл, в котором нет нужного ключа
- **THEN** запуск отклонён с именем файла и ключа, каталог прогона не создан

#### Scenario: Провайдеры видны в перечне вкладов

- **WHEN** пользователь запускает `stepcast plugins`
- **THEN** вывод называет встроенный `env-file` и провайдеры плагинов среди вкладов
