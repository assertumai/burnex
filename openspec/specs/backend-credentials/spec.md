## Requirements
### Requirement: Объявление учётных данных бэкенда

Конфигурация SHALL принимать `backends.<id>.credentials.<VAR>` — источник значения переменной `<VAR>` окружения процесса агентского CLI бэкенда `<id>`: `provider` и параметры провайдера секретов соседними ключами.
Имя `<VAR>` MUST соответствовать `^[A-Z_][A-Z0-9_]*$` и MUST NOT начинаться с
`STEPCAST_`. Параметры MUST проверяться схемой провайдера теми же правилами,
что параметры секрета пайплайна. Одно имя MUST NOT одновременно стоять в
`credentials` и в `env` одного бэкенда. Относительные пути параметров MUST
разрешаться от каталога глобального конфига.

#### Scenario: Ключ из связки ключей для Codex

- **WHEN** `~/.stepcast/config.yml` объявляет `backends.codex.credentials.OPENAI_API_KEY` с `provider: keychain`, `service` и `account`
- **THEN** процесс Codex CLI агентского шага получает `OPENAI_API_KEY` со значением из связки ключей

#### Scenario: Неизвестный провайдер

- **WHEN** запись `credentials` называет незарегистрированный провайдер
- **THEN** `stepcast lint` и запуск отклоняют её с путём записи и именем провайдера

#### Scenario: Конфликт с env бэкенда

- **WHEN** одно имя переменной стоит и в `backends.claude.env`, и в `backends.claude.credentials`
- **THEN** разбор конфигурации отклоняет её с именем переменной

### Requirement: Учётные данные разрешаются до старта прогона

Система SHALL разрешать учётные данные каждого бэкенда, которым идёт хотя бы один агентский шаг или судья прогона, до создания каталога прогона и отказывать в запуске при сбое разрешения.
Отказ MUST следовать по тем же правилам, что у секретов пайплайна (провайдер
не зарегистрирован, параметры не проходят схему, ошибка провайдера, пустое,
короче 8 символов или многострочное значение), и MUST называть путь записи
`backends.<id>.credentials.<VAR>`. Учётные данные бэкенда, которым прогон не
пользуется, MUST NOT разрешаться. Возобновление MUST разрешать их заново.

#### Scenario: Неиспользуемый бэкенд

- **WHEN** учётные данные объявлены для `codex`, а все агентские шаги и судьи прогона идут бэкендом `claude`
- **THEN** провайдер для записи `codex` не вызывается, прогон стартует

#### Scenario: Сбой провайдера

- **WHEN** провайдер записи `backends.codex.credentials.OPENAI_API_KEY` отказал
- **THEN** запуск отклонён с путём записи, каталог прогона не создан

### Requirement: Учётные данные доходят только до процесса CLI

Значение учётных данных бэкенда SHALL накладываться последним слоем на окружение процесса агентского CLI этого бэкенда — агентского шага и судьи — поверх `env_deny` и `backends.<id>.env`.
Значение MUST NOT попадать в окружение командных, скриптовых и плагинных
шагов, проверок `expect` и `until`, в пространство подстановки `${env.*}`, в
argv процесса, в замок и в ключ шага. Каждое вхождение значения MUST
маскироваться в журнале прогона так же, как значение секрета пайплайна, и
переменная, значение которой содержит его, MUST NOT раскрываться
подстановкой `${env.*}`.

#### Scenario: Поверх env_deny

- **WHEN** `OPENAI_API_KEY` объявлен в `credentials` бэкенда, а `env_deny` содержит `*_KEY`
- **THEN** процесс CLI агентского шага получает `OPENAI_API_KEY`

#### Scenario: Командный шаг не получает

- **WHEN** в том же прогоне идёт командный шаг
- **THEN** его окружение не содержит значения учётных данных бэкенда

#### Scenario: Маскирование вывода агента

- **WHEN** агент печатает значение учётных данных в поток вывода
- **THEN** поток агента и `stdout.log` шага содержат `***` на месте значения
