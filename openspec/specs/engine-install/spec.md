## Requirements
### Requirement: Скрипт установки раскладывает версию в каталог релизов
Скрипт `install.sh` SHALL собирать выбранную ссылку репозитория во временном каталоге, раскладывать поставку в `<STEPCAST_HOME>/releases/<версия>`, ставить её зависимости без dev-пакетов и только после этого атомарно переключать ссылку `releases/current` на новый релиз.

#### Scenario: Установка тега
- **WHEN** `install.sh --ref v0.3.0` запущен на машине без stepcast
- **THEN** появляется каталог `~/.stepcast/releases/0.3.0` с `dist`, `schema`, `src/builtin`, `package.json`, `install.sh` и `node_modules`
- **AND** `~/.stepcast/releases/current` указывает на него

#### Scenario: Ссылка не тег
- **WHEN** `install.sh --ref main` указывает на коммит `abc1234`
- **THEN** релиз раскладывается в `releases/main-abc1234`

#### Scenario: Сбой сборки не трогает текущий релиз
- **WHEN** сборка или установка зависимостей выбранной ссылки завершается ошибкой
- **THEN** скрипт выходит с ненулевым кодом
- **AND** `releases/current` указывает туда же, куда до запуска

#### Scenario: Повтор той же версии
- **WHEN** `install.sh --ref v0.3.0` запускается, а `releases/0.3.0` уже существует
- **THEN** релиз собирается и раскладывается заново, а не используется прежний каталог

### Requirement: Без ссылки ставится последний тег версии
Без `--ref` скрипт SHALL выбирать наибольший по номеру версии тег вида `vX.Y.Z` репозитория, пропуская пре-релизные теги, а при отсутствии таких тегов — отказывать с подсказкой указать `--ref`.

#### Scenario: Сравнение по версии
- **WHEN** в репозитории есть теги `v0.9.0`, `v0.10.0` и `v0.11.0-rc.1`
- **THEN** ставится `v0.10.0`

#### Scenario: Тегов нет
- **WHEN** в репозитории нет ни одного тега `vX.Y.Z` и `--ref` не задан
- **THEN** скрипт выходит с ненулевым кодом и называет `--ref` в подсказке

### Requirement: Источник установки задаётся флагом
Скрипт SHALL клонировать репозиторий из `--repo <url|путь>`, а без флага — из публичного адреса репозитория stepcast.

#### Scenario: Локальный репозиторий
- **WHEN** `install.sh --repo /path/to/stepcast --ref v0.3.0`
- **THEN** теги и исходники берутся из `/path/to/stepcast` без обращения к сети за кодом

### Requirement: Версия тега совпадает с версией пакета
При установке тега `vX.Y.Z` скрипт SHALL отказывать, если поле `version` в `package.json` этой ссылки не равно `X.Y.Z`.

#### Scenario: Расхождение тега и пакета
- **WHEN** тег `v0.3.0` указывает на коммит с `"version": "0.2.0"`
- **THEN** скрипт выходит с ненулевым кодом, называя обе версии, и `current` не переключается

### Requirement: Скрипт ставит лаунчер команды
Скрипт SHALL ставить `<STEPCAST_BIN_DIR>/stepcast` (по умолчанию `~/.local/bin/stepcast`) симлинком на `<releases>/current/dist/src/bin.js` и сообщать строку для профиля оболочки, если этот каталог не входит в `PATH`.

#### Scenario: Лаунчер переживает обновление
- **WHEN** после установки `v0.3.0` ставится `v0.4.0`
- **THEN** лаунчер не переписывается и вызывает уже `v0.4.0` через `current`

#### Scenario: Чужой файл на месте лаунчера
- **WHEN** на месте лаунчера лежит файл или симлинк, не ведущий в каталог релизов, и `--force` не задан
- **THEN** скрипт не перезаписывает его и выходит с ненулевым кодом, называя путь

### Requirement: Паспорт установки описывает способ установки
Движок SHALL читать `<STEPCAST_HOME>/install.json` как дискриминированную по полю `method` запись со способами `managed` (поля `repo`, `ref`, `version`, `releases_dir`, необязательное `bin_dir`), `checkout` (поле `dir`) и `npm` (поле `package`), допуская неизвестные ключи и отказывая с причиной при неизвестном способе, нехватке поля способа или невалидном JSON.

#### Scenario: Паспорт managed
- **WHEN** `install.json` содержит `{"method":"managed","repo":"…","ref":"v0.3.0","version":"0.3.0","releases_dir":"/h/.stepcast/releases"}`
- **THEN** разбор возвращает способ `managed` с этими полями

#### Scenario: Лишний ключ
- **WHEN** паспорт содержит ключ, которого схема не знает
- **THEN** разбор проходит, ключ игнорируется

#### Scenario: Неизвестный способ
- **WHEN** паспорт содержит `"method":"brew"`
- **THEN** разбор завершается ошибкой, называющей допустимые способы

#### Scenario: Нет обязательного поля
- **WHEN** паспорт `checkout` не содержит `dir`
- **THEN** разбор завершается ошибкой, называющей поле `dir`

### Requirement: Скрипт установки пишет паспорт managed
После успешного переключения `current` скрипт SHALL записывать `install.json` со способом `managed`, репозиторием, ссылкой, версией, каталогом релизов, каталогом лаунчера и временем установки.

#### Scenario: Паспорт после установки
- **WHEN** `install.sh --repo R --ref v0.3.0` завершился успешно
- **THEN** `install.json` разбирается как `managed` с `repo` R, `ref` `v0.3.0` и `version` `0.3.0`

### Requirement: Без паспорта способ выводится из места движка
При отсутствии `install.json` движок SHALL выводить способ из корня исполняемого пакета: путь внутри `node_modules` — `npm`, корень в git-дереве — `checkout` с этим корнем, иначе — отказ с подсказкой поставить движок через `install.sh`.

#### Scenario: Глобальный npm
- **WHEN** паспорта нет, а корень движка — `/usr/local/lib/node_modules/stepcast`
- **THEN** способ — `npm` с пакетом из `package.json` этого корня

#### Scenario: Рабочее дерево
- **WHEN** паспорта нет, а корень движка — чекаут git
- **THEN** способ — `checkout` с `dir`, равным корню

#### Scenario: Релиз без паспорта
- **WHEN** паспорта нет, а корень движка — каталог в `~/.stepcast/releases`
- **THEN** вывод отказывает, подсказывая `install.sh`

### Requirement: Команда update обновляет движок способом его установки
Команда `stepcast update [--ref <ссылка>]` SHALL обновлять движок по способу из паспорта: `managed` — запуском `install.sh` из `<releases_dir>/current` с репозиторием паспорта, ссылкой флага или последним тегом и каталогами `STEPCAST_HOME`/`STEPCAST_BIN_DIR` установки; `checkout` — `git pull --ff-only` (или `git checkout <ссылка>`), `npm ci` и `npm run build` в каталоге дерева; `npm` — `npm install -g <пакет>@<ссылка|latest>`.

#### Scenario: Managed без новых версий
- **WHEN** паспорт `managed` со ссылкой `v0.3.0`, а последний тег — `v0.3.0`
- **THEN** команда печатает, что обновлений нет, ничего не собирает и выходит с кодом 0

#### Scenario: Managed из сборки ветки
- **WHEN** паспорт `managed` со ссылкой `main` и версией `0.3.0`, а последний тег — `v0.3.0`
- **THEN** запускается `install.sh` с `--ref v0.3.0`: совпадение версии package.json не делает сборку ветки тегированным релизом

#### Scenario: Managed на новую версию
- **WHEN** паспорт `managed` со ссылкой `v0.3.0`, а последний тег — `v0.4.0`
- **THEN** запускается `<releases_dir>/current/install.sh` с `--repo` паспорта и `--ref v0.4.0`, даже если сама команда запущена из чекаута

#### Scenario: Checkout с отцеплённым HEAD
- **WHEN** способ `checkout`, HEAD отцеплён прежним `--ref` тегом или sha, а `--ref` не задан
- **THEN** команда отказывает до любых шагов с подсказкой назвать ссылку через `--ref`

#### Scenario: Грязное дерево checkout
- **WHEN** способ `checkout`, а в дереве есть незакоммиченные правки
- **THEN** команда отказывает с ненулевым кодом до любых `git`-изменений и сборки

#### Scenario: Npm с версией
- **WHEN** способ `npm` с пакетом `stepcast` и задан `--ref 0.4.0`
- **THEN** исполняется `npm install -g stepcast@0.4.0`

#### Scenario: Сломанная конфигурация проекта
- **WHEN** `stepcast update` вызван в каталоге с невалидной конфигурацией stepcast
- **THEN** команда работает, не читая конфигурацию

### Requirement: После обновления поднятый демон перезапускается
После успешного обновления без `--no-restart` команда `update` SHALL перезапускать демон витрины новой версией: загруженный агент launchd — через `launchctl kickstart -k`, живой отсоединённый демон — остановкой и `stepcast up` новой версии в каталоге из его записи; не поднятый демон не поднимается.

#### Scenario: Агент launchd
- **WHEN** агент `ai.stepcast.daemon` загружен и обновление прошло
- **THEN** вызывается `launchctl kickstart -k gui/<uid>/ai.stepcast.daemon`

#### Scenario: Отсоединённый демон
- **WHEN** отсоединённый демон жив, его запись содержит `cwd` `/p`, и обновление прошло
- **THEN** демон останавливается, а `up` новой версии запускается в `/p`

#### Scenario: Запись без каталога
- **WHEN** отсоединённый демон жив, но его запись не содержит `cwd`
- **THEN** демон не останавливается, команда печатает, как перезапустить витрину вручную, и выходит с кодом 0

#### Scenario: Демон не поднят
- **WHEN** ни агента, ни живого демона нет
- **THEN** после обновления никакой демон не запускается

#### Scenario: Обновление не удалось
- **WHEN** сборка новой версии завершилась ошибкой
- **THEN** демон не трогается, а команда выходит с ненулевым кодом

### Requirement: Выпуск версии описан
Репозиторий SHALL содержать документ о выпуске, описывающий порядок: версия в `package.json`, тег `vX.Y.Z` того же коммита, публикация npm-пакета с этого тега, а также откат на прежний релиз; публикация SHALL собирать пакет сама через `prepack`.

#### Scenario: Упаковка собирает dist
- **WHEN** `npm pack` выполняется в чистом чекауте без `dist/`
- **THEN** пакет содержит собранный `dist/src/bin.js`
